## 0-b. 주요 내부 로직 핵심

- **만세력 계산**: 생시 입력 → POST /api/manse → 사주 원국·합충형파해·지장간·신살·용신·점수(8영역) 자동 계산 → localStorage
- **concern·pattern 하드코딩**: 고민/패턴 선택 화면 없음. 항상 `{ concern: '전반적인 운세', pattern: '일반 상담' }` [SO-1]
- **캘리브레이션 훅**: B_HOOK → `HOOK_SYSTEM_YEOKSULGA`(daily) / `HOOK_SYSTEM_PREMIUM`(premium) → C_CALIBRATING(3버튼) → 상세 입력 → B_ACK(템플릿, LLM 없음) → B(해석 LLM에 calibration context 주입)
- **해석 프롬프트**: B → `INTERPRET_SYSTEM_DAILY`(9섹션, 생활상담형) / `INTERPRET_SYSTEM_PREMIUM`(12섹션, 리포트형) — `lib/prompts/interpret.ts`
- **QnA·정리 프롬프트**: D → `QNA_SYSTEM`(= INTERPRET_SYSTEM + 후속질문 suffix), F → `SUMMARY_SYSTEM`(= INTERPRET_SYSTEM + 정리 suffix) — `lib/prompts/qna.ts`, `summary.ts`
- **질문 카운터**: questionCountRemaining 3→2→1→0, 0 도달 시 자동 F 전환
- **4지선다 조건**: sessionCount >= 2 AND turnNumber === 2 AND 50% 확률 → 상태 E 발동. **현재 미작동** — 화면 1 submit마다 sessionCount 0 리셋 [SO-2]
- **정리 응답 트리거**: counter === 0(자동) 또는 "이제 됐어요"(사용자 조기 종료) 두 경로 모두 F 진입
- **sessionCount 증가**: DONE 전환 시 `saveProfile({ ...p, sessionCount: p.sessionCount + 1 })`
- **부모 생시 배너**: turnNumber === 3 시에만 표시. 저장 버튼 → `setView('done')` 만 호출, API/localStorage 저장 없음 [SO-3]
- **자동 스크롤**: 항상 최하단 (`scrollIntoView({ behavior: 'smooth' })`, 스마트 스크롤 없음)
- **마크다운 렌더링**: ReactMarkdown + remark-gfm (테이블 포함)

# 1. A-1 요약 블록

## 핵심 가설
"28~34세 여성이 AI 역술가 해석을 받고 3번 질문을 다 쓰고 정리까지 완주한다."

## A-1 Phase 구조
| Phase | 내용 | 대응 화면 |
|---|---|---|
| P0: 진입 & 재료 수집 | 생시 입력, 만세력 계산, 톤 선택 | 화면 1, 2 |
| P1: 긴 해석 응답 | 캘리브레이션 훅 + 긴 해석 스트리밍 | 화면 3 (A~B 상태) |
| P2: Q&A 루프 | 질문 최대 3회, 4지선다(조건부) | 화면 3 (C~E 상태) |
| P3: 정리 & 저장 & 요청 | 정리 응답, 부모 생시 조건부 요청 | 화면 3 (F~DONE) + 화면 4 |

## MVP 경계
- **제품**: 웹 단일 채널 (모바일 최적화), 익명 세션 (localStorage uuid)
- **타겟**: 이직·연애·결혼 고민이 있는 28~34세 여성
- **목표 행동**: 해석 완독 후 질문 3번 다 쓰고 정리 완주 — 10명 지인 테스트로 검증

### 4-b. UX 의도

- **기본값 이홍규·1976/01/03·23:00**: 개발·테스트용 프리필. 실제 서비스에서는 빈 값이어야 함 [SO-결정 필요 — 별도 판단]
- **음력 입력 옵션**: 음력 생일이 더 익숙한 연령대 사용자 포용. 양력 기본.
- **시간 모름 옵션**: 시간을 모르는 경우가 많음. 체크 시 AI 해석에 "시간 미상" 반영.
- **드롭다운 (자유 타이핑 아님)**: 입력 오류 방지. 만세력 계산 입력값이므로 엄격한 형식 필요.

### 4-c. 인터랙션

- 이름 타이핑 → 텍스트 표시
- [남성]/[여성] 클릭 → 선택 상태 전환
- [양력]/[음력] 클릭 → 탭 전환 (음력 선택 시 윤달 checkbox 표시)
- 윤달 checkbox 체크/해제 → isLeapMonth 상태 토글
- 연/월/일 드롭다운 → 선택값 반영
- 시간 드롭다운 → 선택값 반영
- "시간 모름" 체크 → 시간 드롭다운 disabled 처리 (값 무시)
- [사주 보기] 클릭 → POST /api/manse → `saveProfile({ ...입력값, manse: 응답, sessionCount: 0 })` → router.push('/result')

### 4-d. 상태

- **"15초만 더" 프레임**: 부담 최소화. 숫자(15초)로 시간 체감 제공.
- **두 경로 선택**: 부모 정보 없으면 환경 정보로 대체 가능. 어느 쪽도 없으면 "다음에요" 허용.
- **저장 미구현**: 현재 배너 노출만 구현. Supabase 연동 후 실제 저장 추가 예정 [SO-3].

### 4-c. 인터랙션

- **banner**: [부모님 정보] 클릭 → parent view / [자라온 환경] 클릭 → env view / [다음에요] 클릭 → done view
- **parent**: 라디오 선택 → [저장] 활성 / [저장] 클릭 → "잘 모르거나 건너뛸게요" 선택 시 env view, 그 외 done view
- **env**: 경제·분위기 라디오 각 1개 선택 → [저장] 활성 / [저장] 클릭 → done view
- **done**: "감사해요." 정적 표시 (이후 인터랙션 없음)

### 4-d. 상태

- **조건 미충족 (turnNumber < 3)**: 배너 미표시
- **banner**: 초기 상태
- **parent**: 라디오 선택 전 [저장] disabled
- **env**: 경제·분위기 둘 다 선택 전 [저장] disabled
- **done**: "잘 모르거나 건너뛸게요" → env로 전환 후 done 가능
- ⚠ **저장 버튼 실제 저장 없음**: `setView('done')` 만 호출 — localStorage/API 저장 미구현 [SO-3]

## Claude의 적대적 압박 — "지금 이 화면 설계를 죽일 이유 세 가지"

**Kill 이유 1: 화면 3이 너무 많은 상태를 한 URL에 집어넣어 사용자가 현재 어디 있는지 인지 불가**

12개 상태(A → B_HOOK → C_CALIBRATING → C_CALIBRATING_DETAIL/NO → B_ACK → B → C → D → E → F → DONE)가 전부 `/chat` 한 URL에 있다. 훅 → 캘리브레이션 → 해석 → Q&A → 정리가 시각적으로 연속 스크롤 형태로 쌓인다. 사용자가 스크롤을 올려서 이전 내용을 읽다가 입력창을 보면 "지금 내가 뭘 해야 하는지" 맥락을 잃을 수 있다. 특히 캘리브레이션 단계가 메시지 스트림 사이에 묻히면 훅 질문에 대한 응답인지 일반 AI 메시지인지 구분 어려움. 상태별 헤더 변경이나 진행 인디케이터가 없어 현재 Phase를 사용자가 인지할 방법이 없다.

**Kill 이유 2: 화면 2의 만세력 표가 28~34세 여성 타겟의 진입 장벽이 될 수 있음**

화면 2는 사주 원국 4주 표 + 십신 + 신살 + 오행 + 천을귀인 + 용신 + 대운 + 세운 + 월운까지 전부 보여준다. "갑·갑·경·병 / 자·자·자·진"을 보고 이게 자신에 대한 무언가라는 걸 이해하지 못하는 사용자는 이 화면에서 이탈한다. 핵심 가설 검증을 위해선 "화면 2를 읽고 [프리미엄 리포트형]을 클릭하는가"가 선행 조건인데, 사주 표가 복잡해서 이탈하면 화면 3 진입 자체가 안 된다. 사주 미지식자에게 화면 2는 공부 숙제처럼 보일 수 있음.

**Kill 이유 3: 부모 생시 요청(화면 4)이 저장 없이 노출되면 사용자 신뢰를 소비한다**

3번 완주한 사용자에게 "15초만 더 주실래요?"라고 묻고, 실제로 입력을 받지만 저장하지 않는다. 다음 세션에서 "지난번에 알려주신 부모님 정보를 반영해서..."같은 개인화가 없다면, 이 배너는 신뢰를 얻고 아무것도 제공하지 않는 빈 약속이 된다. 10명 지인 테스트에서 2회차 방문자가 있다면 "지난번 알려줬는데 왜 또 물어봐?"가 나올 수 있음. Supabase 연동 전 이 배너를 노출하는 것은 신뢰 부채를 쌓는 것.
