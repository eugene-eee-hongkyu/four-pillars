# A-1. 사주톡 — 문서를 프로세스로

> **이 문서의 1차 독자는 나 자신이다.**
> Claude와 AI 빌드 도구는 2차 독자.
> 내 생각을 눈으로 보기 위해 Claude의 도움으로 꺼내 쓴 문서다.

---

## 1. A-0 요약 블록

**핵심 가설**
이직·연애·결혼 고민이 있는 28~34세 여성이, 링크로 받은 웹 사주 서비스에서, 긴 해석을 읽은 뒤 스스로 최대 3번의 추가 질문을 써가며 대화를 완주할 것이다.

**러프 유즈케이스 메인 라인**
링크 접속 → 생시+고민 입력 → 반복 패턴 4지선다 → 만세력 주입 긴 해석(5~8문장) → 최대 3번 사용자 자유 질문 → 정리 응답 → 세션 DB 누적 → (3번 다 쓴 사용자) 부모 생시 요청

**MVP 경계 3개**

| 항목 | 고정 |
| --- | --- |
| 제품 | AI 대화형 사주 해석 웹서비스 |
| 타겟 | 28~34세 여성, 수도권, 이직·연애·결혼 고민. Eugene 지인 10명 |
| 목표 행동 | 3번 질문 다 쓰고 정리까지 완주 (보조: 1번 이상 질문 후 완주) |

---

## 2. Phase 구조 개요

```
P0. 진입 & 재료 수집 (5 Step)
    사용자가 링크 접속해 생시·고민·반복 패턴 답을 입력

P1. 긴 해석 응답 (2 Step)
    만세력+고민+패턴답을 프롬프트에 주입해 역술가 톤 5~8문장 해석

P2. 사용자 주도 Q&A 루프 (3 Step, 최대 3회)
    사용자가 자유 질문, AI 답변, 카운터 차감, 루프 or 종료

P3. 정리 & 저장 & 조건부 요청 (3 Step)
    정리 응답 + DB 저장 + (3번 다 쓴 사용자) 부모 생시 요청
```

## 3. Phase별 Step 상세

### P0. 진입 & 재료 수집

**S1. 생시 입력 (첫 세션만)**

- 사용자: 링크 접속 → 랜딩 → 생년월일·성별·태어난 시간 입력. 시간 모름 체크박스 선택 가능
- 시스템: 입력값 저장. 만세력 계산 엔진에 전달해 원국 데이터(천간·지지·십성 등) 생성. 2회차부터는 이 Step 스킵하고 저장된 만세력 로드

**S2. 고민 입력**

- 사용자: "지금 어떤 고민이세요?" 텍스트 필드에 한 줄~두 줄 입력. placeholder 예시 노출 ("이직을 할지 말지 고민", "만나는 사람과 결혼해도 될지")
- 시스템: 입력 텍스트 저장

**S3. 고민 영역 자동 판별 (비가시)**

- 사용자: 없음
- 시스템: LLM이 고민 텍스트를 3영역(이직·일 / 연애 / 결혼) + 기타로 분류. 기타일 경우 일반 반복 패턴 4지선다 fallback. 분류 결과는 S4 질문 선택에 쓰임

**S4. 반복 패턴 4지선다 (1회)**

- 사용자: 영역별 맞춤 4지선다 중 하나 탭. 예(이직 영역): "일과 관련해 반복되는 게 있나요? (A) 잘 되다가 갑자기 그만두고 싶어짐 (B) 처음엔 재미있다가 금방 식음 (C) 남들은 버티는데 나만 못 버팀 (D) 잘 모르겠다"
- 시스템: 선택값을 해석 프롬프트 재료로 저장

**S5. 시작 안내 배너**

- 사용자: "해석을 준비하고 있어요. 다 읽으신 후 궁금한 건 최대 3번까지 물어보실 수 있어요" 메시지 1~2초 노출 후 S6 자동 진입
- 시스템: 질문 카운터 3으로 초기화. UI에 "질문 3번 남음" 표시

### P1. 긴 해석 응답

**S6. 긴 해석 생성·스트리밍**

- 사용자: 입력창 disabled 상태. 해석 말풍선이 5~8문장 구체적으로 스트리밍되는 걸 읽음
- 시스템: LLM 프롬프트 조합 — [만세력 원국 데이터] + [고민 텍스트] + [반복 패턴 답] + [이전 세션 DB 있으면 요약] + [역술가 톤 지침]. 2회차 이상이면 "지난번 ○○ 고민 때 말씀하신 거랑 연결해서..." 식 맥락 참조 포함

**S7. 해석 완료 + 입력창 활성**

- 사용자: 해석 끝나면 "혹시 더 궁금한 거 있으세요?" 프롬프트 노출. 입력창 enabled, "질문 3번 남음" 카운터 보임
- 시스템: 카운터 상태 유지. 사용자가 입력 없이 떠나도 재촉 안 함

### P2. 사용자 주도 Q&A 루프 (최대 3회)

**S8. 사용자 질문 입력·전송**

- 사용자: 자유 질문 타이핑 후 전송. 예: "그럼 지금 이직하는 게 맞아요?", "새로 만난 사람이랑 오래 갈 수 있어요?"
- 시스템: 입력창 disabled. 카운터 1 차감 ("2번 남음" → "1번 남음" → "마지막 질문")

**S9. AI 답변 스트리밍**

- 사용자: 답변 스트리밍 읽음
- 시스템: [사용자 질문] + [만세력] + [이전 대화 전체 맥락] + [반복 패턴 답] 주입. 원 해석과 모순 안 되게 일관성 유지. **2회차 이상 세션 + 이번이 2번째 질문 응답이면** 답변 말미에 추가 4지선다 1개 삽입. 이 4지선다 답은 (a) 3번째 질문 답변 세밀화 재료로 쓰고 (b) 정리 응답에도 반영하고 (c) 세션 DB에도 저장 (세 군데 모두 활용)

**S10. 답변 완료 → 루프 분기**

- 사용자:
    - 질문 남아있음 → 입력창 활성 → S8 루프 or "이제 됐어요" 버튼 탭
    - 3번 다 씀 → 자동 P3
- 시스템: 카운터 체크. 분기 처리

### P3. 정리 & 저장 & 조건부 요청

**S11. 정리 응답**

- 사용자: 지금까지 대화의 핵심을 묶은 응답 읽음. 밀도는 질문 횟수에 비례 (0회=짧게, 3회=풍부하게)
- 시스템: [만세력] + [고민] + [반복 패턴 답] + [Q&A 기록 전체] + [2회차+ 4지선다 답 있으면 반영] 주입, 정리 프롬프트로 LLM 호출

**S12. 대화 DB 저장 (비가시)**

- 사용자: 없음
- 시스템: 세션 전체 기록(고민, 반복 패턴 답, Q&A, 삽입 4지선다 답, 정리 응답) DB 저장. 다음 세션 해석에 자동 참조됨

**S13. 조건부 부모 생시 요청**

- 사용자: **3번 질문 다 쓴 사용자만** 보게 됨. "오늘 대화 어떠셨어요? 다음에 오실 때 더 정확하게 봐드릴 수 있어요. 15초만 더 주실래요?" → [부모님 정보 알려주기 / 자라온 환경 답하기 / 다음에요] 3지선다
    - 부모님 정보 선택 시 fallback 폼: 두 분 모두 생시 → 생년월일만 → 한 분만 → 모름 (모름 선택 시 환경 질문으로 전환)
    - 환경 질문: 어린 시절 경제 상태 5단계 + 집 분위기 5단계. 무거운 단어(조실부모, 이혼 등)는 UI에서 부드러운 표현으로 대체
- 시스템: 질문 카운터 < 3이면 S13 스킵, 바로 세션 종료. "다음에요" 선택 시 플래그 저장 → 3번째 세션 시작 시 1회만 재시도

## 4. 머릿속 시뮬레이션 체크

**시나리오 1: 이직 고민 여성 첫 세션, 3번 질문 다 씀**

"링크 받고 접속. 생년월일시 입력 15초. '지금 어떤 고민이세요?' → '이직 결정 못 내리고 있어요' 타이핑. 4지선다 → A(잘 되다가 갑자기 그만두고 싶어짐) 탭. '질문 3번 가능' 배너. 긴 해석 스트리밍. '원국상 안정보다 성장을 쓰는 타입' 읽다가 '어 맞네'. 해석 끝. '그럼 지금 이직하는 게 맞아요?' 질문 → 답변. 카운터 2. '어떤 직장이 맞아요?' 질문 → 답변. 카운터 1. '올해 안에 가는 게 좋을까요?' 질문 → 답변. 카운터 0. 자동 정리 응답. '15초만 더 주세요' 부모님 요청 배너. 부모님 정보 탭 → 두 분 생시 입력. 종료."

→ 막히는 지점: 없음

**시나리오 2: 연애 고민 여성 2회차 세션, 2번만 씀**

"두 번째 방문. 생시 입력 스킵. '어떤 고민이세요?' → '만나는 사람이랑 결혼 얘기 나왔는데 확신이 안 서요'. 4지선다 연애 영역 → B(처음엔 설레는데 시간 지나면 식음) 탭. 배너. 해석: '지난번 이직 고민 때 말씀하신 성장 욕구랑 연결해서...' 읽으면서 '오 기억하네'. 해석 끝. '이 사람이랑 결혼해도 돼요?' 질문 → 답변. 카운터 1. '언제쯤 결혼하면 좋을까요?' 질문 → 답변 스트리밍. 답변 끝자락에 '혹시 이런 경험 있으신지요? (A) 중요한 결정 앞에 늘 망설임 (B) 주변 의견에 휘둘림 (C) 직감 따랐다가 후회 (D) 잘 모르겠다' 4지선다 나타남 → A 탭. 카운터 여전히 1. '이제 됐어요' 탭. 정리 응답 뜸. (정리에 A 반영됨: '중요한 결정 앞에 망설이는 패턴이 연애에서도 드러나네요'.) 부모 생시 요청 안 옴. 종료."

→ 막히는 지점: 없음

## 5. 플래너 결정 항목 (모두 해결됨)

- **결정 1 (재방문 2번째 답변 4지선다 답 활용)**: B+C 병행 확정. 정리 응답 반영 + DB 누적
- **결정 2 (고민 영역 자동 판별 방식)**: A 확정. LLM 자동 분류
- **결정 3 (기타 영역 처리)**: A 확정. 일반 반복 패턴 4지선다 fallback

부모 생시 입력 폼 fallback 구조는 과거 대화에서 확정 — 두 분 모두 → 생년월일만 → 한 분만 → 모름 시 환경 질문.

## 6. Kill / Go / Hold 판정

**Go — A-2로 진입**

근거 3줄:

1. Phase 4개 구조가 A-0 메인 라인을 빈틈없이 커버. 시뮬레이션 2개 모두 막히는 지점 없음
2. Step 13개가 사용자·시스템 행동 짝으로 모두 명시됨. [SO 결정 필요] 3개 이번 턴에 해결. 미해결 이슈 없음
3. 남은 결정(UI 배치·카운터 표시 형태·입력 폼 구체 UX 등)은 A-2(화면 결정) 영역. A-1 단계에서 더 붙잡고 있는 건 비효율

## Claude의 적대적 압박 — 이 프로세스를 죽일 이유 세 가지

**1. P1 긴 해석의 품질이 만세력 주입만으로는 보장 안 됨.**
"만세력을 프롬프트에 주입하면 해석 품질이 올라간다"는 Eugene 가정을 A-0에서 받아들였지만, 프롬프트 엔지니어링 실제로는 만세력 외에 [역술가 톤 지침] 품질이 결정적. 이 지침을 Claude·Eugene 중 누구도 아직 안 씀. S6가 구현 단계에서 "예상보다 일반론적 해석이 나옴" 실패 모드 빠질 위험 매우 높음. A-2 전에 프롬프트 프로토타입 1회 돌려보는 게 낫다.

**2. 2회차 4지선다 삽입이 P2 흐름을 끊음.**
S9에서 "답변 말미에 4지선다 자연스럽게 삽입"이라 적었지만, 실제 UX에서는 긴 답변 끝에 갑자기 선택지 버튼이 뜨는 형태다. 사용자는 "자유 질문 중인데 왜 객관식?"으로 느낄 수 있음. 자연스러움 확보가 답변 텍스트 + 버튼 UI의 합작이라 A-2에서 실제로 구현해보기 전에는 OK인지 Kill인지 모름. A-1에서는 구조만 잡힌 상태.

**3. "3번 질문 다 씀" 목표 행동의 희귀성.**
핵심 가설 검증 기준이 "3번 다 씀"인데, 10명 지인 테스트에서 이 기준 통과자가 0~2명이면 가설 검증 불가능. 사용자들이 1~2번 질문만 쓰고 만족해서 나가면 "쉽게 풀어주는데 내 얘기네" 검증 축이 작동한 것일 수도, 안 한 것일 수도 있어 판별 불가. 보조 지표 "1번 이상 질문 후 완주"를 함께 봐도 이 기준은 여전히 느슨함. 가설을 10명으로 검증 가능한지 자체가 구조적 위험.
