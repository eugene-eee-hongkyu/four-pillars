## 1. A-1 요약 블록

**핵심 가설**
이직·연애·결혼 고민이 있는 28~34세 여성이, 링크로 받은 웹 사주 서비스에서, 긴 해석을 읽은 뒤 스스로 최대 3번의 추가 질문을 써가며 대화를 완주할 것이다.

**Phase 구조**
- P0. 진입 & 재료 수집
- P1. 긴 해석 응답 (역술가 톤: 훅 → 캘리브레이션 → 확인 → 해석 순서)
- P2. 사용자 주도 Q&A 루프 (최대 3회)
- P3. 정리 & 저장 & 조건부 요청

**MVP 경계 3개**

| 항목 | 고정 |
|---|---|
| 제품 | AI 대화형 사주 해석 웹서비스 |
| 타겟 | 28~34세 여성, 수도권, 이직·연애·결혼 고민. Eugene 지인 10명 |
| 목표 행동 | 3번 질문 다 쓰고 정리까지 완주 (보조: 1번 이상 질문 후 완주) |

## 2. 화면 목록

| 라우트 | 컴포넌트명 | 설명 |
|---|---|---|
| `/` | `ScreenBirthInput` | 생년월일·시간 입력 폼 |
| `/concern` | `ScreenConcern` | 고민 카드 선택 (4개) |
| `/pattern` | `ScreenPattern` | 반복 패턴 4지선다 |
| `/result` | `ScreenResult` | 만세력 결과 + 해석 스타일 선택 |
| `/chat` | `ScreenChat` | 대화 화면 (상태 A~F + DONE) |

**주의**: 원본 A-2는 화면 순서를 `생시 입력 → 고민 → 패턴 → 대화`로 기술했으나,
코드에서는 `/` (생시 입력) → `/result` (만세력 결과) → `/chat` (대화) 경로와
`/` → `/concern` → `/pattern` → `/chat` 경로가 **공존**한다.
두 경로는 별도의 진입점을 가지며, `/result` 화면이 분기점 역할을 한다.

## 3. 화면 간 전환 흐름

### 3-a. 전체 Wireflow

```
[/] 생시 입력
   │
   │ handleSubmit → /api/manse POST → saveProfile
   ▼
[/result] 만세력 결과
   │
   ├─ "다시 입력" 버튼 → router.push('/')
   ├─ "복사" 버튼 → navigator.clipboard (화면 이동 없음)
   ├─ "현실 풀이형" 버튼 → saveConversation({concern:'전반적인 운세', pattern:'일반 상담', tone:'reality'})
   │                     → router.push('/chat')
   └─ "생활 상담형" 버튼 → saveConversation({concern:'전반적인 운세', pattern:'일반 상담', tone:'daily'})
                         → router.push('/chat')

[/concern] 고민 선택          ← /result 에서는 이 화면으로의 push 없음
   │                             (concern 화면은 독립 진입 경로)
   │ 로드 시: loadProfile() null → router.replace('/')
   │
   ├─ 이직/연애/결혼 카드 탭
   │   → saveConversation({concern: card.label, concernCategory: card.value, pattern: ''})
   │   → router.push('/pattern')
   │
   └─ "직접 쓸게요" → textarea 입력 → "다음" 버튼
       → /api/classify POST → resolvedCategory
       → saveConversation({concern: freeText, concernCategory: resolved, pattern: ''})
       → router.push('/pattern')

[/pattern] 반복 패턴
   │ 로드 시: loadProfile() 또는 loadConversation() null → router.replace('/')
   │
   └─ 카드 탭
       → saveConversation({...conv, pattern: option})
       → router.push('/chat')

[/chat] 대화 화면
   │ 로드 시: loadProfile() null → router.replace('/')
   └─ (화면 내부 상태 전환, 외부 router.push 없음)
```

### 3-b. 두 경로 요약

| 경로 | 설명 |
|---|---|
| `/` → `/result` → `/chat` | tone 선택 경로. concern='전반적인 운세', pattern='일반 상담' |
| `/concern` → `/pattern` → `/chat` | 고민/패턴 선택 경로. concern·pattern 값이 채워짐 |

두 경로 모두 `/chat`으로 합류한다. `/result`에서 `/concern`으로 가는 경로는 코드에 없다.

#### 4-b. 표시 항목 전체 (코드 확인)

- **헤더 버튼 2개**: `variant="outline"` "다시 입력" (`router.push('/')`), `variant="outline"` "복사" (`navigator.clipboard`)
- **해석 스타일 버튼 2개** (grid 2열):
  - `tone='reality'`, label=`'현실 풀이형'`, desc=`'직장·돈·관계 현실 언어'`
  - `tone='daily'`, label=`'생활 상담형'`, desc=`'가족·일상·생활 중심'`
- **인적 정보**: `{name} ({koreanAge(birthYear)}세)`, `{year}년 {month}월 {day}일{HH:mm} (양력)` (시간 미상이면 시간 부분 생략)
- **사주 그리드**: 기둥 순서 `[시주, 일주, 월주, 년주]` (rawPillars 인덱스 0~3)
  - 천간 십신 행 (`getStemSipsin`)
  - 천간 박스 (w-14 h-14, 오행 색상, 한자+한글)
  - 지지 박스 (w-14 h-14, 오행 색상, 한자+한글)
  - 지지 십신 행 (`getBranchSipsin`)
- **신살·길성** (`hasShensha` true일 때만): 길성(녹색 뱃지) vs 흉살(붉은 뱃지)
  - GILSEONG_SET: `건록, 천덕귀인, 월덕귀인, 학당귀인, 천의성, 암록, 문창귀인, 금여성`
- **오행 분포**: 목·화·토·금·수 순서 (`ELEMENT_ORDER`)
- **천을귀인**: `guiinPositions.length > 0`일 때만
- **용신**: `manse.yongsin` 있을 때만 (`reasoning` 텍스트)
- **대운/세운/월운**: `manse.luckCycles` 있을 때만 (각각 가로 스크롤 테이블)

#### 4-c. 인터랙션

- 로드 시 `loadProfile()` null 또는 `profile.manse` falsy → `router.replace('/')`
- "다시 입력" 탭 → `router.push('/')`
- "복사" 탭 → `navigator.clipboard.writeText(buildCopyPrompt())` → 2초 후 `setCopied(false)` 복원
- 해석 스타일 버튼 탭 → `saveConversation({ concern: '전반적인 운세', pattern: '일반 상담', tone })` → `router.push('/chat')`

#### 4-d. 상태

| 상태 | 동작 |
|---|---|
| 기본 | profile.manse 있으면 전체 렌더 |
| 복사 직후 | 버튼 label `'복사됨 ✓'`, 2초 후 복원 |
| profile/manse 없음 | `return null` (아무것도 렌더 안 함) |

#### 4-b. 상태 전이 규칙 (chatReducer 확인)

```
A --[tone='reality'|'daily']→ B_HOOK (START_HOOK, 1.5초 타이머)
A --[그 외]→ B (START_INTERPRETING, 1.5초 타이머)

B_HOOK --[HOOK_DONE]→ C_CALIBRATING
C_CALIBRATING --[CALIBRATE_INITIAL(yes|other)]→ C_CALIBRATING_DETAIL
C_CALIBRATING --[CALIBRATE_INITIAL(no)]→ C_CALIBRATING_NO
C_CALIBRATING_DETAIL --[CALIBRATE_DONE]→ B_ACK
C_CALIBRATING_NO --[CALIBRATE_DONE]→ B_ACK
B_ACK --[ACK_DONE, 800ms 후 자동]→ B

B --[INTERPRETATION_DONE]→ C
C --[SEND_QUESTION]→ D (questionCountRemaining -1, turnNumber +1)
D --[ANSWER_DONE(triggerInline=true)]→ E
D --[ANSWER_DONE(triggerInline=false, remaining=0)]→ F (isAutoTransition=true)
D --[ANSWER_DONE(triggerInline=false, remaining>0)]→ C

C|E --[DONE_EARLY]→ F (isAutoTransition=false)

```

## 6. [확인 필요] 항목

코드에서 확인은 되나 원본 A-2와 다르거나 추가 결정 필요한 것들.

1. `/concern` 화면으로 가는 진입 경로가 코드에 명시적으로 없음. `/result`에서 `/concern`으로의 `router.push` 없음. `/concern`은 직접 URL 접근 또는 다른 외부 링크에서만 진입 가능한 것으로 보임 — 의도된 구조인지 확인 필요.

2. `B_ACK`의 `other` 분기에서 `yearStr && catStr` 조합이 코드에 하나만 정의됨 (`yearStr && catStr` → `yearStr 단독` 없음). `other` + yearStr만 있고 catStr 없는 경우 두 번째 else 분기 (`catStr` 단독) 또는 마지막 else로 떨어짐 — 의도인지 확인 필요.

3. `CAL_YEARS`는 `CURRENT_YEAR - 4 + i` (i=0~4) → `Array.from({length:5})` + `CURRENT_YEAR` 중복 구조. 실제로 `[CURRENT_YEAR-4, ..., CURRENT_YEAR-1, CURRENT_YEAR, CURRENT_YEAR, 'multiple', 'before']` 7개 + 마지막 `CURRENT_YEAR` 가 concat으로 추가됨 — 중복 여부 코드 재확인 필요.

4. `ParentRequestBanner`에서 입력 데이터(`parentLevel`, `envEconomy`, `envAtmosphere`)가 localStorage/API에 저장되는 로직 없음 (`setView('done')` 만 실행). 저장 미구현 상태인지 의도적 생략인지 확인 필요.

5. `sessionCount` 증가는 `SUMMARY_DONE` (phase F 완료) 시 실행됨. `loadProfile().sessionCount`가 첫 세션=0으로 저장되고 정리 완료 후 1이 됨 — `shouldTriggerInlineChoice`의 `sessionCount >= 2` 조건은 세 번째 방문부터 발동.
