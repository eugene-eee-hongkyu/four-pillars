# 05 사주톡 내부 프로세스 — 계산 흐름 및 AI 호출 명세

> 어느 시점이 내부 계산이고, 어느 시점에 AI에 묻는지, AI에게 무엇을 어떻게 묻는지를 기술한다.

---

## 전체 흐름 한눈에 보기

```
[화면 1] 생년월일 입력
    ↓
[내부 계산 #1] 만세력 + 6개 모듈 계산 (AI 없음)
    ↓
[화면 2] 결과 화면 — 사주 그리드 표시 (AI 없음)
    ↓
[화면 3] 톤 선택 (역술가 / 과학형 / 예시형 / 심리상담가)
    ↓
[AI 호출 #1] 초기 해석 스트리밍 (interpret)
    ↓
[AI 호출 #2~4] 사용자 질문 답변 — 최대 3회 (qna)
    ↓
[AI 호출 #5] 전체 정리 응답 (summary)
```

## 1단계 — 생년월일 입력 (화면 1)

**화면**: `app/page.tsx`  
**사용자가 입력하는 것**: 이름, 성별, 양력/음력, 생년월일, 태어난 시간(선택)

입력 후 "다음" 클릭 → `/api/manse` 호출 (POST)

## 2단계 — 내부 계산 (AI 없음)

### API: `POST /api/manse`
**파일**: `app/api/manse/route.ts` → `lib/manse/engine.ts`

#### 입력값
```json
{ "year": 1975, "month": 3, "day": 15, "hour": 14, "minute": 30, "gender": "male" }
```

#### 내부에서 실행되는 계산 (순서대로)

| 단계 | 함수 | 라이브러리 | 결과 |
|---|---|---|---|
| 사주 4기둥 계산 | `calculateSaju()` | `@fullstackfamily/manseryeok` | 년·월·일·시주 한글+한자, 진태양시 보정 |
| 천간·지지 분리 | `splitPillar()` | 내부 | 각 기둥의 천간(stem), 지지(branch) |
| 오행 분포 계산 | `countElements()` | 내부 | `{wood:3, fire:4, earth:1, metal:0, water:1}` |
| 지장간 추출 | `calcAllJijanggan()` | 내부 | 각 기둥에 숨어 있는 천간 목록 |
| 합충형파해 계산 | `calcHapchunh()` | 내부 | 천간합·지지합·충·형·파·해·공망 목록 + 1줄 요약 |
| 신살·길성 계산 | `calcShensha()` | 내부 | 기둥별 신살 목록, strong(핵심) 목록 |
| 용신 계산 | `calcYongsin()` | 내부 | 용신 오행 + 이유 (억부법 근사) |
| 대운·세운·월운 | `buildLuckCycles()` | 내부 | 대운 목록(10년 단위), 세운 목록(연간), 월운 목록 |

#### 반환값 (`ManseResult`)
```typescript
{
  yearPillar, monthPillar, dayPillar, hourPillar,        // "갑자", "무오" 형식
  yearPillarHanja, monthPillarHanja, ...,                 // "甲子", "戊午" 형식
  elementCounts: { wood, fire, earth, metal, water },
  jijanggan: { yearPillar, monthPillar, dayPillar, hourPillar },  // 각각 string[]
  hapchunh: { cheonganHap, yukHap, samHap, chung, hyeong, pa, hae, gongmang, summary },
  shensha: { yearPillar, monthPillar, dayPillar, hourPillar, strong },
  yongsin: { primary, secondary, reasoning },
  luckCycles: { daeun[], sewun[], wolwun[] },
  summary,   // "년주: 갑자(甲子), 월주: 무오(戊午), ..." 형식 텍스트
}
```

이 전체 객체가 **localStorage (`sajutalk_profile.manse`)에 저장**된다.

## 3단계 — 결과 화면 표시 (AI 없음)

**화면**: `app/result/page.tsx`  
localStorage에서 ManseResult를 읽어 렌더링한다.

표시 항목:
- 사주 4기둥 그리드 (천간·지지 한자+한글, 오행 색상)
- 십신 (일간 기준 각 기둥의 관계)
- 신살·길성 (기둥별)
- 오행 분포 막대
- 천을귀인 위치
- 용신 (억부법 근사)
- 대운·세운·월운 표

이 화면에서 **4가지 해석 스타일 버튼**을 선택 → 채팅 시작.

## 4단계 — 톤 선택 → 채팅 시작

- `saveConversation({ concern: '전반적인 운세', pattern: '일반 상담', tone: 'science' })`

`tone`은 localStorage(`sajutalk_conversation`)에 저장된다.

## AI 호출 #1 — 초기 해석 (interpret)

**화면**: `app/chat/page.tsx` → 상태 B 진입 시 자동 실행  
**API**: `POST /api/interpret`  
**파일**: `app/api/interpret/route.ts`  
**모델**: claude-sonnet-4-6  
**max_tokens**: 4096  
**방식**: 서버 사이드 스트리밍

### 시스템 프롬프트 — 톤별 분기

`getInterpretSystem(tone)` 함수로 선택:

#### 역술가 (`yeoksulga`)
```
당신은 30년 경력의 사주명리 역술가입니다.
전통 명리 언어로 사주를 풀이합니다.

[핵심 원칙]
- "~하는 형상입니다", "~의 기운이 작동합니다" 어조
- 운명적 흐름 강조, 신살·합충의 영향력 구체적 언급
- 따뜻하고 위안이 되는 마무리

[출력 형식]
[천명(天命) 개요] → [성품과 기질] → [직업과 재물의 흐름]
→ [지금의 운세] → [주의할 점] → [건강과 인연] → [맺음말]
```

#### 과학형 (`science`) — 기본값
```
당신은 명리학 데이터를 분석하는 심리 분석가이자 통계 기반 상담가입니다.

[핵심 원칙]
1. 확률 언어 필수: "약 7~8할은", "데이터상", "통계적으로"
2. 결론 먼저 → 근거 → 구체적 장면 순서
3. 불확실성 인정: "물론 같은 구조도 환경에 따라 다르게 나타나요"
4. 시간 특정 필수: "30대 초반에", "이 대운이 끝나는 XX년까지"
5. 누구에게나 맞는 말 금지

[출력 형식]
[핵심 분석] → [성격·의사결정 패턴] → [적성·업무 스타일]
→ [현재 운세 분석] → [주의 패턴·보완 전략]
→ [재물 흐름] → [건강 패턴] → [종합 인사이트]
(50대 이상: [관계·배우자 패턴] [자녀·주변 관계] 추가)
```

#### 예시형 (`example`)
```
당신은 명리학 데이터로 연도별 사건 확률을 예측하는 분석가입니다.

[핵심 원칙]
1. "~이 일어났을/일어날 가능성 N%이다" 형식 필수
2. 추상 표현 절대 금지: "이사를 갔을 가능성 90%", "이직 제안을 받았을 가능성 75%"
3. 과거: 역검증 형식 / 현재·미래: 분기별 표 형식

[출력 형식]
[사주 핵심 구조 1문장]
[연도별 사건 분석 — 최근 10년]
  ### XXXX년 (○○년 / X세)
  - 일: [사건] 가능성 N%
  - 금전: [사건] 가능성 N%
  - 연애·관계: [사건] 가능성 N%
  - 건강: [사건] 가능성 N%
[현재 연도 분기별 예측 표]
[반복 패턴 요약]
```

#### 심리상담가형 (`counselor`)
```
당신은 명리학을 심리상담 도구로 활용하는 상담가입니다.

[핵심 원칙]
1. 공감 먼저: "그런 느낌이 드는 데는 이유가 있어요"
2. 취약성을 강점으로 재해석
3. 섹션마다 내면 탐색 문장 1개: "지금 이 부분이 어떻게 느껴지세요?"
4. 행동 처방보다 자기 이해 우선

[출력 형식]
[당신의 핵심 에너지] → [내면의 욕구와 두려움] → [관계에서의 나]
→ [일과 성취에서의 나] → [지금 이 시기 — 당신에게 필요한 것]
→ [자기 돌봄 제안] → [함께 탐색해볼 것]
```

## AI 호출 #2~4 — Q&A (qna)

**트리거**: 사용자가 채팅창에 질문 입력 후 전송 (최대 3회)  
**API**: `POST /api/qna`  
**파일**: `app/api/qna/route.ts`  
**모델**: claude-sonnet-4-6  
**max_tokens**: 4096  
**방식**: 스트리밍

### 시스템 프롬프트

`getQnaSystem(tone)` = `getInterpretSystem(tone)` + 아래 추가 규칙:

```
[Q&A 추가 규칙]
- 사용자 질문에 직접 답변. 원 해석과 모순 없이 일관성 유지
- 4기둥 원국 + 합충형파해 + 신살·길성 + 대운·세운 + 반복 패턴 + 이전 대화 전체 맥락 활용
- 5~8문장. 질문 성격에 따라 조금 더 길어도 됨
- 현재 대운·세운 데이터 있으면 반드시 활용: "지금 ○○ 대운 데이터상 이 시기에는..."
- 합충 정보 있으면 활용: "월일이 충하는 구조라서 이 패턴이 나타나는 거예요"
- 사용자가 과거 사건을 공유하면 해당 연도 세운과 연결해 역검증 먼저 제시
- 확률 언어 필수
- Sycophancy 금지: 원국 근거 있으면 사용자가 원하지 않는 답도 말함

- 2회차 세션 + 이번이 2번째 질문 + 50% 조건이면 답변 말미에
  "혹시 이런 경험 있으세요?" 4지선다 4개 삽입. 답변 본문과 구분선.
```

### 유저 메시지 — `buildQnaPrompt(ctx)`

```
사용자 이름: 홍길동

[분석 기준일]: 2026-04-25

[사주 4기둥]
년주: 을묘(乙卯)
월주: 무진(戊辰)
일주: 갑인(甲寅)  ← 핵심 일주
시주: 갑오(甲午)

[지장간]
년주: 갑, 을
월주: 을, 계, 무
일주: 무, 병, 갑
시주: 병, 기, 정

[오행 분포]
木(나무) 6개 (55%), ...

[합충형파해]
월일 지지 인묘 목국(반합), ...

[신살·길성] — strong 항목 답변에 활용
★ 강조: 건록, 학당귀인

[용신] — 해석 방향에만 활용, 사용자에게 직접 노출 금지
木(나무) 과다(55%) → 金(쇠)이 용신

[운세 흐름] — 반드시 현재 대운·세운 언급, 확률 언어 사용
현재 대운: 49세 시작 계미(癸未)(정인·정재 대운)
현재 세운: 2026년 병오(丙午)(편관)
현재 월운: 2026년 4월 임진(壬辰)

[고민·반복 패턴]
고민: 전반적인 운세
반복 패턴 답: 일반 상담

이전 대화:          ← 2번째 이후 질문부터 포함
Q: 이직 타이밍이 언제가 좋을까요?
A: (이전 AI 답변 전체)

현재 질문: 2026년 하반기 금전운은 어때요?

# 조건부 (2회차 세션 + 2번째 질문 + 50% 확률 발동 시):
답변 말미에 아래 구분선과 함께 4지선다를 추가하세요:
---
혹시 이런 경험 있으세요?
A. 잘 되다가 갑자기 흥미 잃음
B. 내가 잘 할 수 있을지 걱정됨
C. 주변 시선이 신경 쓰임
D. 잘 모르겠다
```

### 4지선다 조건 (조건 모두 충족 시 발동)
- `sessionCount >= 1` (2회차 이상 방문)
- `turnNumber === 2` (이번 질문이 2번째)
- `Math.random() < 0.5` (50% 확률)

## AI 호출 #5 — 정리 요약 (summary)

**트리거**: ① 3번 질문을 다 써서 자동 전환 ② 사용자가 "이제 됐어요" 클릭  
**API**: `POST /api/summary`  
**파일**: `app/api/summary/route.ts`  
**모델**: claude-sonnet-4-6  
**방식**: 스트리밍

### 시스템 프롬프트

`SUMMARY_SYSTEM` = `INTERPRET_SYSTEM(과학형)` + 아래 추가 규칙:

```
[정리 응답 추가 규칙]
- 지금까지 대화 맥락 전체를 데이터 기반으로 종합 정리
- 밀도는 질문 횟수 비례:
  * 0회 (이제 됐어요 바로): 3~4문장 핵심만
  * 1~2회: 5~7문장 — Q&A에서 추가로 파악된 패턴 포함
  * 3회 다 씀: 8~12문장 — 누적 Q&A 종합 + 행동 제안 1~2개
- 자동 전환이면 맨 앞에 "세 번 질문하셨으니 오늘 분석을 정리해드릴게요"
- 확률 언어 유지
```

## AI가 절대 받지 않는 것

- 사용자의 실제 이름 외 개인 식별 정보 (이메일, 전화번호 등)
- API 키, 환경 변수
- 용신 계산 결과의 "용신은 ○○" 노출 금지 (시스템 프롬프트로 차단)
- 지장간 용어 직접 노출 금지 (풀어서 설명하도록 강제)
