# 04 A-3 화면을 디자인으로 v1

> 00 기획 하네스 정책 v11을 토대로 한다. 작성 전 정책 문서의 "안 읽힘 6원인"·"문장 원칙"·"AI의 역할"·"번들링"·"변경 가시화"·"턴 카운팅"을 참조한다.

---

## 이 문서 사용법

A-3은 **하네스의 네 번째 핵심 문서**이다. A-2에서 확정된 와이어프레임을 **시각 디자인 결정**으로 옮긴다. "화면을 디자인으로" 옮긴다는 뜻이다.

**A-3의 정체성: 타겟에 맞는 시각 언어 결정.**

A-2까지는 구조(와이어프레임)와 UX 의도였다. A-3는 그 위에 **시각 톤·컬러·폰트**를 박는다. 28~34세 여성 사주 서비스와 50대 남성 비즈니스 SaaS는 같은 디자인일 수 없다. 타겟이 다르면 시각 언어가 달라야 사용자가 "이건 내 거구나" 느낀다.

**왜 별도 단계인가:**

A-2(구조) → A-3(시각) → B-1(빌드)로 분리하지 않으면 빌드 도구 AI가 디폴트 디자인으로 채운다. 결과는 평균값. 모든 MVP가 비슷하게 보인다. 사용자 검증 축("쉽게 풀어주는데 내 얘기네" 같은)은 디자인 톤에 영향받기 때문에 디자인 빠진 MVP는 검증 축이 흐려진다.

**도구 — Claude Design 디폴트, Stitch 무료 대안:**

- **Claude Design (디폴트)**: claude.ai 안에서 텍스트 → React 코드 직접 생성. **Claude Code handoff bundle 지원** — B-1 진입 자연스러움. 코드베이스 ingest 가능 (이미 코드 있는 경우). Pro 이상 유료.
- **Stitch (무료 대안)**: Google 무한 캔버스 디자인 도구. Figma export. 비용 0. 단 Claude Code로 가려면 Figma 거쳐야 함.

이 문서에는 두 가지가 같이 들어 있다:
1. **산출물 템플릿** — A-3 산출물이 최종적으로 어떤 형태여야 하는가
2. **워크플로우** — Claude와 플래너가 어떤 순서로 채워가는가

Claude는 이 문서와 기획 하네스 정책 v11을 함께 읽은 뒤 A-3 작성을 시작한다.

A-0(타겟·핵심 가설) + A-2(화면·UX 의도)가 A-3의 입력이다. A-2 없이 A-3 진입 불가.

A-3 산출물이 Go로 끝나면 B-1로 진입. B-1의 §4 프로젝트 구조에 A-3에서 결정된 디자인 토큰(CSS 변수·Tailwind config) 또는 Claude Design handoff bundle이 들어간다.

## A-3 단계의 정체성

**함의 1. Claude 주도, 플래너는 선택만.**
타겟 분석 → 톤 후보 → 컬러 후보 → 폰트 후보를 Claude가 옵션으로 제시. 플래너는 A/B/C 선택만. 디자이너 없는 플래너가 디자인 시스템을 0에서 결정하는 건 부담이지만, 옵션 + 추천 받아서 고르는 건 가능.

**함의 2. 1차 독자는 빌드 도구 AI.**
A-3 산출물의 1차 독자는 Claude Design 또는 Stitch. 그래서 모든 결정은 **AI가 정확히 해석할 수 있는 형태**로 작성한다. 추상 표현 금지. "따뜻한 톤" → "warm dark purple #2D1B3D + gold #C9A961" 수준.

**함의 3. UI까지 확정 스펙.**
정책 v11 철학과 일치 — "스펙은 확정적이어야 한다". A-2가 UX 확정 스펙이었다면 A-3는 UI 확정 스펙. 매번 다른 결과 안 나옴.

## 산출물 형태 (분량 제한 없음)

> **분량 구분**
> - **이 문서 (템플릿+워크플로우)**: 분량 제한 없음. 작성 가이드다.
> - **A-3 산출물**: 분량 제한 없음. AI가 읽고 디자인 생성할 문서. 빠진 내용 없게 충실히.

### 산출물 구조

A-3 산출물의 최종 형태는 아래 6개 섹션으로 구성된다.

```
[맨 앞] 1차 독자 선언문 (1차 독자는 빌드 도구 AI, 플래너는 §2·§5 선택만)

1. A 트랙 요약 블록
   - A-0 핵심 가설 + 타겟
   - A-2 화면 목록

2. 디자인 방향 결정 (플래너 선택)
   2-a. 톤 (따뜻함·차가움·신비로움·실용 등)
   2-b. 컬러 팔레트 (HEX 코드)
   2-c. 폰트 페어링 (제목·본문)
   2-d. 보이스·텍스트 톤

3. 핵심 화면별 디자인 의도
   각 화면이 어떤 시각 분위기여야 하는지
   와이어프레임(A-2) → high-fidelity 전환 시 가이드

4. 빌드 도구 인계 정보
   4-a. Claude Design 프롬프트 초안 (디폴트)
   4-b. 디자인 토큰 (CSS 변수·Tailwind config) — B-1 직접 import용
   4-c. Stitch 프롬프트 초안 (무료 대안 사용 시)

5. [SO 결정 필요] 항목

6. Kill / Go / Hold 판정

[맨 끝] Claude의 적대적 압박 — "Kill할 이유 세 가지"
```

### 섹션별 상세

#### 1. A 트랙 요약 블록

A-0·A-2 산출물의 핵심을 맨 앞에 고정. A-3 작업 중 "지금 무슨 디자인인지"를 잊지 않도록.

- **A-0 핵심 가설 한 문장**
- **A-0 타겟 (3 누가 쓰는가)**
- **A-2 화면 목록** (이름·번호만)
- **MVP 경계 3개**

#### 2. 디자인 방향 결정 (플래너 선택)

**2-a. 톤**

타겟에 맞는 시각 톤 결정. Claude가 옵션 3개 + 추천 + 이유.

**좋은 예시 (사주톡):**
```
타겟: 28~34세 여성, 수도권, 이직·연애·결혼 고민

톤 옵션:
- 옵션 A: 신비로운 + 따뜻한 (어두운 보라 + 골드)
  + 사주의 "운명·해석" 분위기와 정합
  + 몰입감 — 긴 해석을 진지하게 읽도록
  - 어두운 톤이라 일부 사용자 부담 가능
- 옵션 B: 모던·실용 (밝은 베이지 + 짙은 네이비)
  + 거부감 적음
  + 첫 방문 진입 장벽 낮음
  - 사주의 신비감 약화
- 옵션 C: 따뜻한 미니멀 (연한 핑크 + 따뜻한 회색)
  + 28~34세 여성 타겟에 친숙
  - 사주 도메인의 무게감 부족

Claude 추천: A (신비로운 + 따뜻한)
이유: 핵심 가설이 "긴 해석을 끝까지 읽고 3번 질문"인데,
이 행동은 몰입 환경에서 더 자주 일어남. A의 어두운 보라 + 골드는
"역술가 대면" 분위기를 시각으로 구현 — A-1 §1 메인 라인의
"유명 역술가 톤" 텍스트와 정합.
```

**나쁜 예시:**
```
모던하고 깔끔한 디자인.
```
이유: 추상적. AI 빌드 도구가 "모던"을 어떻게 해석할지 매번 다름.

**2-b. 컬러 팔레트**

확정된 톤 위에 구체 HEX 코드. 4~6색.

**좋은 예시 (사주톡 — 톤 A 선택 시):**
```
| 역할 | 이름 | HEX | 용도 |
|------|------|-----|------|
| Primary | Deep Purple | #2D1B3D | 배경, 헤더 |
| Secondary | Indigo Black | #1A1428 | 카드 배경 |
| Accent | Antique Gold | #C9A961 | 버튼·강조·카운터 |
| Text Primary | Warm White | #F5F0E8 | 본문 텍스트 |
| Text Secondary | Muted Gold | #8C7A4F | 보조 텍스트 |
| Error | Crimson | #B85450 | 에러 상태 |
```

**나쁜 예시:**
```
보라색 + 금색
```
이유: 어떤 보라·어떤 금인지 모름. AI 빌드 도구가 매번 다르게 선택.

**2-c. 폰트 페어링**

제목·본문 폰트 결정. 무료 웹 폰트(Google Fonts) 우선.

**좋은 예시 (사주톡):**
```
| 역할 | 폰트 | 두께 | 용도 |
|------|------|------|------|
| 제목 | Cormorant Garamond | 500 | 화면 헤더, 정리 응답 |
| 본문 | Pretendard | 400 | 긴 해석, 사용자 대화 |
| 강조 | Pretendard | 600 | 카운터, 버튼 라벨 |

대안 한국어 폰트 옵션:
- Noto Serif KR (역술가 톤 강함)
- Pretendard (모던, 가독성 양호)

Claude 추천: 제목 Cormorant Garamond + 본문 Pretendard
이유: 영문 제목 폰트의 격조 + 한글 본문의 가독성 균형.
사주 도메인의 신비감(영문 세리프)과 28~34세 사용자의
모던 가독성(한글 산세리프) 둘 다 충족.
```

**2-d. 보이스·텍스트 톤**

UI 텍스트(라벨·에러 메시지·placeholder)의 어조 결정. 시각만큼 중요.

**좋은 예시 (사주톡):**
```
보이스: 부드러운 존중 (역술가 톤이지만 위압 없음)

규칙:
- 존댓말 (반말 금지)
- "~요" 종결 (~다 금지)
- 명령 금지 — "입력하세요" 대신 "알려주실래요?"
- 에러는 사용자 책임 안 묻기 — "다시 한번만 알려주실래요" 같은 톤

예시:
- 입력 placeholder: "이직을 할지 말지 고민이라면..." (예시형)
- 카운터: "질문 3번 남음" (압박 없음)
- 에러: "잠시 멈췄어요. 다시 시도해볼까요?" (책임 분산)
```

#### 3. 핵심 화면별 디자인 의도

A-2의 모든 화면을 다 high-fidelity로 만들 필요 없다. **핵심 2~3개**만 디자인 의도 명시. 나머지는 빌드 도구가 결정된 디자인 시스템으로 자동 생성.

**핵심 화면 선정 기준:**
- 핵심 가설 검증에 직접 관련된 화면
- 사용자가 가장 오래 머무는 화면
- 첫인상 결정 화면

**좋은 예시 (사주톡 — 화면 4 긴 해석 응답):**
```
화면 4: 긴 해석 응답 (S6·S7)

디자인 의도:
- 배경: Primary (Deep Purple). 어두운 톤이 "긴 해석을 차분히 읽는" 분위기 유도
- 해석 텍스트: Warm White, Cormorant Garamond × Pretendard 페어링.
  세리프 영문 + 한글 산세리프가 격조 + 가독성
- 카운터 "질문 3번 남음": Antique Gold, 우측 상단.
  골드는 시각 무게가 있어서 사용자가 자연스럽게 의식 — UX 의도 직결
- 입력창 disabled 상태: Indigo Black 배경 + 50% opacity.
  "지금은 못 쓴다"가 시각적으로 전달
- 입력창 enabled 후: 부드러운 골드 보더 등장 (transition 300ms).
  "이제 질문해도 돼요" 시각 신호

A-2 §4 UX 의도와의 연결:
- "질문 카운터 우측 상단 고정" → 골드 컬러로 구현
- "입력창 disabled 유지 → enabled 전환" → opacity + border transition
- "1~2초 여유 후 프롬프트 노출" → fade-in 1500ms
```

**핵심 화면 외 나머지 화면**:
"화면 1~3, 5~8은 위 디자인 시스템(2-a~2-d)과 화면 4 의도를 따라 빌드 도구가 자동 생성. 단 화면 7(정리 응답)은 화면 4와 같은 헤더·카운터 사라짐(완료 표시) 적용."

#### 4. 빌드 도구 인계 정보

**4-a. Claude Design 프롬프트 초안 (디폴트)**

플래너가 Claude Design에 복붙할 프롬프트. 사주톡처럼 코드 이미 있는 경우 코드베이스 ingest 활용.

**좋은 예시:**
````
[Claude Design 프롬프트 — 사주톡]

[코드베이스 연결]
GitHub repo: [URL]
또는 ZIP 업로드: [경로]

[목표]
사주톡 MVP에 디자인 시스템 적용. 현재 디폴트 톤이라
타겟(28~34세 여성, 인생 전환기)에 안 맞음.

[디자인 방향]
톤: 신비로운 + 따뜻한 (어두운 보라 + 골드)
컬러:
  Primary: #2D1B3D (Deep Purple)
  Secondary: #1A1428 (Indigo Black)
  Accent: #C9A961 (Antique Gold)
  Text Primary: #F5F0E8 (Warm White)
  Text Secondary: #8C7A4F (Muted Gold)
  Error: #B85450 (Crimson)

폰트:
  제목: Cormorant Garamond 500
  본문: Pretendard 400
  강조: Pretendard 600

보이스: 부드러운 존중. 존댓말, 명령 금지, 에러는 사용자 책임 안 묻기.

[핵심 화면 디자인 요구]
화면 4 (긴 해석 응답):
- 카운터 "질문 3번 남음" 우측 상단, Antique Gold
- 입력창 disabled 상태 명확히 시각화 (opacity 50%)
- 입력창 enabled 전환 시 골드 보더 fade-in
- 해석 텍스트 가독성 우선 (line-height 1.7)

[다른 화면들]
위 디자인 시스템 따라 자동 생성.

[제약]
- 기능 변경 금지 (시나리오 1·2 그대로 작동)
- React/Next.js + Tailwind 유지
- 기존 컴포넌트 구조 최대한 보존, 스타일만 갱신

[출력]
Claude Code handoff bundle.
````

**4-b. 디자인 토큰 (B-1 직접 import용)**

Claude Design 안 쓰고 Claude Code에 직접 적용하는 경우용. CSS 변수와 Tailwind config 형태.

**좋은 예시:**
```css
/* design-tokens.css */
:root {
  --color-primary: #2D1B3D;
  --color-secondary: #1A1428;
  --color-accent: #C9A961;
  --color-text-primary: #F5F0E8;
  --color-text-secondary: #8C7A4F;
  --color-error: #B85450;

  --font-serif: 'Cormorant Garamond', serif;
  --font-sans: 'Pretendard', sans-serif;

  --transition-fade: 300ms ease-in-out;
  --transition-slow: 1500ms ease-in-out;
}
```

```js
// tailwind.config.js 추가분
module.exports = {
  theme: {
    extend: {
      colors: {
        primary: '#2D1B3D',
        secondary: '#1A1428',
        accent: '#C9A961',
        'text-primary': '#F5F0E8',
        'text-secondary': '#8C7A4F',
      },
      fontFamily: {
        serif: ['Cormorant Garamond', 'serif'],
        sans: ['Pretendard', 'sans-serif'],
      },
    },
  },
};
```

**4-c. Stitch 프롬프트 초안 (무료 대안)**

Claude Design 안 쓰는 경우 Stitch에 던질 프롬프트. 기본은 4-a와 비슷하지만 Stitch는 코드베이스 ingest 안 됨 → 텍스트로만 설명.

#### 5. [SO 결정 필요] 항목

정책 v11 원칙 5 적용. 옵션 + 추천 + 이유 필수.

**A-3에서 흔한 결정 항목:**
- 톤 A/B/C 중 선택
- 폰트 페어링 (영문+한글 조합)
- 다크모드 지원 여부
- 애니메이션 강도 (subtle vs. dramatic)

**금지 패턴:**
- ❌ `[SO 결정 필요] 톤 어떻게 할까요?` (옵션 없음)

**필수 패턴:**
- ✅ 톤 옵션 A/B/C + 각 장단점 + Claude 추천 + 이유 (핵심 가설 연결)

#### 6. Kill / Go / Hold 판정

A 트랙·B 트랙과 동일.

- **Go** — B-1 진입. 근거 3줄.
- **Kill** — 여기서 종료. 근거 3줄.
- **Hold** — 외부 정보 확보 후 재판정. 무엇을 알아야 하는지 명시. 최대 2회.

**A-3 단계 Hold이 흔한 이유:**
- 타겟이 명확하지 않음 (A-0 회귀 필요)
- Claude Design 또는 Stitch 도구 접근 권한 미확보
- 핵심 화면 디자인 의도 결정에 외부 검증 필요

---

### 산출물 마지막 (Claude의 적대적 압박)

정책 v11 역할 1. Claude가 자동으로 맨 아래에 "지금 이 디자인 결정을 Kill할 이유 세 가지" 첨부. A-3 단계 Kill 이유는 **디자인 결정의 구조적 결함**을 찌른다.

예시:
- "톤 A(어두운 보라)가 28~34세 여성의 모바일 환경에서 가독성 떨어질 가능성. 실기기 테스트 없이 결정"
- "폰트 페어링 Cormorant + Pretendard 조합이 한글 비율과 시각 균형 안 맞을 가능성"
- "핵심 화면 디자인 의도가 화면 4에만 집중. 화면 7(정리 응답)이 빌드 도구 디폴트로 가면서 톤 깨질 위험"

## 워크플로우 (채우는 순서)

A-3 산출물 작성은 **Claude 주도 + 플래너 선택**. 5턴 상한.

### STEP 0: 시작 선언 및 A-0·A-2 확인

**플래너의 행동:**
- `A-3 시작` 선언
- A-0·A-2 산출물 첨부 (또는 같은 대화창 이어서)

**Claude의 행동:**
- 턴 카운팅 시작
- A-2가 Go 판정 안 됐으면 A-3 진입 불가
- A-0 타겟·A-2 화면 목록 추출해 §1 작성

### STEP 1: 톤 + 컬러 + 폰트 옵션 번들 제시

**Claude의 행동:**
- 타겟 분석
- §2-a 톤 옵션 3개 + 추천
- §2-b 컬러 팔레트 옵션 3개 (각 톤별)
- §2-c 폰트 페어링 옵션 2~3개
- §2-d 보이스·텍스트 톤 초안
- 한 응답에 번들

**예시 응답 형식:**
```
[A-3 진행: 턴 1/5]

A-0 타겟(28~34세 여성, 인생 전환기) + A-2 화면 8개 확인.

§2 디자인 방향 옵션 번들 — 한 번에 선택해주세요:

[톤 옵션 A/B/C + 추천 본문]
[컬러 팔레트 옵션 본문]
[폰트 페어링 옵션 본문]
[보이스 초안]

이 셋 다 답해주시면 다음 턴에 §3 핵심 화면 디자인 의도로 갑니다.
```

**플래너의 행동:**
- 톤·컬러·폰트 일괄 선택
- 보이스 수정 지시 있으면 반영

### STEP 2: 핵심 화면 디자인 의도 + 빌드 도구 인계 정보

**Claude의 행동:**
- 확정된 톤·컬러·폰트로 §3 핵심 화면 디자인 의도 작성
- §4-a Claude Design 프롬프트 초안
- §4-b 디자인 토큰 (CSS 변수·Tailwind config)
- §4-c Stitch 프롬프트 초안 (옵션)

**플래너의 행동:**
- 핵심 화면 의도 검토
- §4 도구 선택 (Claude Design vs Stitch vs 직접 토큰 import)

### STEP 3: 플래너가 도구에서 디자인 생성 (직접 작업)

**플래너의 행동:**
- §4-a 또는 §4-c 프롬프트 복붙해 Claude Design / Stitch에서 생성
- 변형 비교, 인라인 코멘트로 수정
- 결과 첨부 (Claude Design 결과 스크린샷 또는 Stitch Figma 링크)

**Claude의 행동:**
- 플래너가 결과 가져올 때까지 대기 (이 턴은 플래너 외부 작업)
- 결과 받으면 검토 — 타겟·UX 의도와 정합성 분석

### STEP 4: 검토 + 조립 + Kill 이유 + 판정 추천

**Claude의 행동:**
- 디자인 결과 검토 결과 + 보완 지시 (필요 시)
- 전체 A-3 산출물 클린 조립
- 맨 아래 "Kill할 이유 세 가지"
- Go/Kill/Hold 추천 + 근거 3줄

**플래너의 행동:**
- Claude 추천대로 확정 또는 수정

### STEP 5: Go 확정 시 자동 파일 저장

**Claude의 행동:**
- 파일명: `04_A-3_화면을_디자인으로_[프로젝트명].md`
- 저장 위치: `/mnt/user-data/outputs/`
- 변경 가시화 마크 모두 제거한 클린본

Go 후 플래너에게 전달할 메시지:
```
A-3 산출물 저장 완료. 다음 단계 옵션:

옵션 X (Claude Design 사용):
  - Claude Design 결과를 "Hand off to Claude Code" 클릭
  - 자동 생성된 handoff bundle을 B-1 입력으로 전달
  - B-1은 빌드보다는 "이미 디자인 적용된 코드를 검증·정리"

옵션 Y (Stitch + 디자인 토큰 사용):
  - §4-b 디자인 토큰을 B-1 입력으로
  - B-1 §4 프로젝트 구조에 design-tokens.css·tailwind.config 적용
  - 빌드 도구가 토큰 기반으로 화면 생성

다음: B-1 시작 선언 + 위 입력 첨부
```

A-3 산출물의 턴 상한은 **5턴**. 70% 경고는 **4턴째**. A-0과 동일.

| 턴 | 플래너 메시지 | Claude 응답 |

## A-3 산출물에서 흔한 실패 모드

**실패 1: 톤이 추상**
- 예: "모던하고 깔끔하게"
- 왜 나쁜가: AI 빌드 도구가 "모던"을 매번 다르게 해석. 확정 스펙 아님
- 교정: 옵션 3개로 구체화 + HEX 코드 + 이유

**실패 2: 컬러가 색 이름만**
- 예: "보라색 + 금색"
- 왜 나쁜가: 어떤 보라·어떤 금인지 모름
- 교정: HEX 코드 + 역할 명시 (Primary·Accent 등)

**실패 3: 폰트 페어링 한국어 폰트 누락**
- 예: 영문 폰트만 명시
- 왜 나쁜가: 한글 사용자 타겟인데 한글 폰트 미정 → AI가 디폴트 폰트로 채움
- 교정: 영문·한글 둘 다 명시. 무료 웹 폰트(Google Fonts) 우선

**실패 4: 핵심 화면 너무 많이 선정**
- 예: 화면 8개 모두 디자인 의도 작성
- 왜 나쁜가: 분량 폭증 + Claude Design 프롬프트 길어짐 + 모든 화면 일관성 검증 부담
- 교정: 2~3개만 (핵심 가설 직결 화면). 나머지는 디자인 시스템 따라 자동

**실패 5: A-2 UX 의도와 단절**
- 예: "카운터 우측 상단 골드"라고만 적고 A-2의 UX 의도와 연결 안 함
- 왜 나쁜가: 디자인이 UX 의도 안 살림 → 핵심 가설 검증 약화
- 교정: 각 디자인 결정 옆에 "A-2 §4 UX 의도와의 연결" 명시

**실패 6: 빌드 도구 인계 정보 추상**
- 예: "디자인 시스템 적용해주세요"
- 왜 나쁜가: 빌드 도구가 매번 다른 결과 — 확정 스펙 아님
- 교정: HEX·폰트명·transition ms 등 모두 명시

**실패 7: 보이스·텍스트 톤 누락**
- 예: 시각만 결정하고 UI 텍스트 톤 안 박음
- 왜 나쁜가: 빌드 도구가 디폴트 텍스트 ("입력하세요" 같은) 사용 → 톤 깨짐
- 교정: §2-d에 보이스 규칙 + 예시 텍스트

**실패 8: Claude Design 프롬프트에 코드베이스 ingest 안 활용**
- 예: 사주톡처럼 이미 코드 있는데 텍스트로만 설명
- 왜 나쁜가: Claude Design의 강점(코드베이스 ingest)을 못 살림. 결과가 기존 구조와 안 맞을 수 있음
- 교정: §4-a 프롬프트에 GitHub repo 링크 또는 ZIP 업로드 명시

## B-1 진입 조건 (Go 판정 시)

A-3가 Go로 끝나면 B-1 진입 가능. **다음 셋 모두 만족 시만:**

1. **A-3 산출물 파일 저장됨** (`04_A-3_화면을_디자인으로_[프로젝트명].md`)

이 셋 중 하나라도 미충족이면 B-1 진입 불가.
