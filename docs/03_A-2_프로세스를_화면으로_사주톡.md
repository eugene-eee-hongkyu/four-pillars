# A-2. 사주톡 — 프로세스를 화면으로

> **이 문서의 1차 독자는 나 자신이다.**
> Claude와 AI 빌드 도구는 2차 독자.
> 내 생각을 눈으로 보기 위해 Claude의 도움으로 꺼내 쓴 문서다.
>
> **이 문서는 실제 코드 기반으로 역산한 A-2다.**
> 코드 읽은 날짜: 2026-04-25. 라우트 5개, 상태 머신 1개, API 라우트 4개 기준.

## 1. A-1 요약 블록

**핵심 가설**
이직·연애·결혼 고민이 있는 28~34세 여성이, 링크로 받은 웹 사주 서비스에서, 긴 해석을 읽은 뒤 스스로 최대 3번의 추가 질문을 써가며 대화를 완주할 것이다.

**Phase 구조**
- P0. 진입 & 재료 수집
- P1. 긴 해석 응답
- P2. 사용자 주도 Q&A 루프 (최대 3회)
- P3. 정리 & 저장 & 조건부 요청

**MVP 경계 3개**

| 항목 | 고정 |
|---|---|
| 제품 | AI 대화형 사주 해석 웹서비스 |
| 타겟 | 28~34세 여성, 수도권, 이직·연애·결혼 고민. Eugene 지인 10명 |
| 목표 행동 | 3번 질문 다 쓰고 정리까지 완주 (보조: 1번 이상 질문 후 완주) |

## 2. 화면 목록

코드베이스 라우트 기준 5개 화면.

| # | 라우트 | 화면명 | A-1 Step 대응 |
|---|---|---|---|
| 1 | `/` | 생시 입력 | S1 (첫 세션만) |
| 2 | `/concern` | 고민 선택 | S2 |
| 3 | `/pattern` | 반복 패턴 4지선다 | S3·S4 |
| 4 | `/result` | 만세력 결과 + 해석 스타일 선택 | P0 보조 화면 (A-1 미명시) |
| 5 | `/chat` | 대화 화면 | S5~S12 + S13(조건부) |

> **A-1과 코드 차이 주의**: A-1에서 화면 구분이 없던 "해석 스타일 선택(톤 선택)"이
> `/result` 라우트로 구현되어 있다. 실제 흐름은
> `/` → `/result` → `/concern` → `/pattern` → `/chat` 이 아니라,
> `/` → `/result`(만세력 계산 후 이동) → (톤 선택 시) `/chat` 또는
> `/concern` → `/pattern` → `/chat`이다.
> 두 경로가 모두 `/chat`으로 수렴한다.

**두 진입 경로 요약**

```
경로 A (고민 기반)    : / → /concern → /pattern → /chat
경로 B (만세력 직접)  : / → /result → /chat (톤 선택)
```

### 화면 1. 생시 입력 (`/`)

#### 4-a. ASCII 와이어프레임

```
┌─────────────────────────────────────┐
│ 사주톡                              │  ← h1
├─────────────────────────────────────┤
│                                     │
│ 반가워요.                           │
│ 먼저 몇 가지만 알려주세요.          │
│                                     │
│ 이름                                │  ← label
│ ┌─────────────────────────────────┐ │
│ │ 이름을 입력하세요               │ │  ← Input (max 20자)
│ └─────────────────────────────────┘ │
│                                     │
│ 성별                                │  ← label
│ ○ 여성   ○ 남성                    │  ← radio
│                                     │
│ 달력                                │  ← label
│ ○ 양력   ○ 음력                    │  ← radio
│ □ 윤달                              │  ← 음력 선택 시만 노출
│                                     │
│ 생년월일                            │  ← label
│ ┌──────┐ ┌──────┐ ┌──────┐         │
│ │년  ▼ │ │월  ▼ │ │일  ▼ │         │  ← select 3개
│ └──────┘ └──────┘ └──────┘         │
│                                     │
│ 태어난 시간                         │  ← label
│ ┌──────┐ ┌──────┐                  │
│ │시  ▼ │ │분  ▼ │                  │  ← select 2개
│ └──────┘ └──────┘                  │
│ □ 시간을 몰라요                     │  ← Checkbox
│                                     │
│ (에러 메시지 영역)                  │
│                                     │
│ ┌─────────────────────────────────┐ │
│ │              다음               │ │  ← Button (w-full)
│ └─────────────────────────────────┘ │
└─────────────────────────────────────┘
```

#### 4-b. UX 의도

- 이름 필드는 해석 본문·정리 응답에서 사용자를 이름으로 부르기 위한 재료. "○○님" 호칭으로 역술가 대면 상담 느낌 구현
- 양력/음력 라디오를 노출해 음력 생일 사용자 이탈 방지. 음력 선택 시 윤달 체크박스 추가 노출
- "시간을 몰라요" 체크박스 제공 — 체크 시 시간·분 select disabled, 만세력 계산 시 12시로 처리(시주 null 반환)
- "다음" 한 번으로 만세력 계산까지 완료 후 `/result`로 이동. 중간 로딩 화면 없음

#### 4-c. 인터랙션

- 이름 타이핑 → 필드에 글자 표시 (maxLength 20)
- 성별 라디오 탭 → 선택 표시 (기본값: 남성)
- 달력 라디오 탭 → 양력/음력 전환; 음력 선택 시 윤달 체크박스 등장; 달력 변경 시 isLeapMonth 초기화
- 생년월일 드롭다운: 년(1950~현재 역순)·월(1~12)·일(1~31)
- 시간 드롭다운: 시(0~23)·분(0/15/30/45 4단계); "시간을 몰라요" 체크 시 disabled + opacity-50
- "다음" 탭 →
  1. 이름 빈 값이면 "이름을 입력해주세요." 에러 표시
  2. 음력이면 `lunarToSolar` 변환; 변환 실패 시 "올바르지 않은 음력 날짜입니다." 에러
  3. `/api/manse` POST 호출 (버튼 "준비 중..." + disabled)
  4. 성공 시 `saveProfile` → `router.push('/result')`
  5. 실패 시 "잠시 후 다시 시도해주세요."

#### 4-d. 상태

| 상태 | 설명 |
|---|---|
| 정상 | 기본값 채워진 폼 (이름 '이홍규', 1976년 1월 3일 23:00, 남성, 양력) |
| 검증 실패 | 이름 미입력 → 에러 메시지 노출 |
| 음력 날짜 오류 | 변환 실패 → 에러 메시지 노출 |
| 로딩 | `/api/manse` 호출 중 → 버튼 "준비 중..." + disabled |
| API 에러 | 만세력 계산 실패 → "잠시 후 다시 시도해주세요." |

### 화면 2. 고민 선택 (`/concern`)

#### 4-a. ASCII 와이어프레임

```
┌─────────────────────────────────────┐
│ 사주톡                              │  ← h1
├─────────────────────────────────────┤
│                                     │
│ ○○님, 지금 어떤 고민이세요?        │  ← name 없으면 "지금 어떤 고민이세요?"
│                                     │
│ ┌─────────────────────────────────┐ │
│ │ 💼 이직·일                      │ │  ← 카드 (value='이직')
│ └─────────────────────────────────┘ │
│ ┌─────────────────────────────────┐ │
│ │ 💕 연애                         │ │  ← 카드 (value='연애')
│ └─────────────────────────────────┘ │
│ ┌─────────────────────────────────┐ │
│ │ 💍 결혼                         │ │  ← 카드 (value='결혼')
│ └─────────────────────────────────┘ │
│ ┌─────────────────────────────────┐ │
│ │ ✏️ 직접 쓸게요                   │ │  ← 카드 (value='직접입력')
│ └─────────────────────────────────┘ │
└─────────────────────────────────────┘

  ↓ "직접 쓸게요" 탭 후 — 같은 화면에서 확장

┌─────────────────────────────────────┐
│ ...                                 │
│ ┌─────────────────────────────────┐ │
│ │ ✏️ 직접 쓸게요  ✓               │ │  ← selected: border-primary + bg-accent
│ └─────────────────────────────────┘ │
│                                     │
│ ┌─────────────────────────────────┐ │
│ │ 예: 이직을 할지 말지 고민이에요 │ │  ← textarea (rows=3, 확장 영역)
│ │     만나는 사람과 결혼해도 될지 │ │
│ └─────────────────────────────────┘ │
│                                     │
│ ┌─────────────────────────────────┐ │
│ │              다음               │ │  ← Button (텍스트 없으면 disabled)
│ └─────────────────────────────────┘ │
└─────────────────────────────────────┘
```

#### 4-b. UX 의도

- 4개 카드 세로 배치 = 화면 3 반복 패턴과 동일 구조. 처음 보는 사용자가 "선택하면 되는구나" 즉시 파악
- 이직·연애·결혼 탭 → 즉시 다음 화면. "직접 쓸게요"만 같은 화면에서 확장 — "3개는 바로 / 1개는 한 단계 더" 차이로 구조 직관 전달
- 직접입력 선택 후 다른 카드 탭 → 텍스트 필드 접히고 해당 영역으로 즉시 이동
- `classifying` 상태에서 모든 카드 disabled. "읽고 있어요..." 버튼으로 사용자가 LLM 분류 진행 중임을 인식

#### 4-c. 인터랙션

- 이직·연애·결혼 카드 탭 →
  1. `setSelected(card.value)`
  2. `saveConversation({ concern: card.label, concernCategory: card.value, pattern: '' })`
  3. `router.push('/pattern')`
- "직접 쓸게요" 카드 탭 → `setSelected('직접입력')`, 텍스트 필드 + "다음" 버튼 확장
- 텍스트 입력 있을 때만 "다음" 버튼 활성
- "다음" 탭 →
  1. `/api/classify` POST 호출 (버튼 "읽고 있어요..." + disabled)
  2. 응답 category 수신
  3. `saveConversation({ concern: freeText, concernCategory, pattern: '' })`
  4. `router.push('/pattern')`
  5. 분류 실패 시 category='기타' fallback

#### 4-d. 상태

| 상태 | 설명 |
|---|---|
| 정상 | 카드 4개, 텍스트 필드 없음 |
| 직접입력 선택 | 해당 카드 border-primary + bg-accent + ✓; 텍스트 필드·버튼 등장 |
| 텍스트 입력 중 | "다음" 버튼 활성 |
| 텍스트 빈 상태 | "다음" 버튼 disabled |
| 분류 중 | 버튼 "읽고 있어요..."; 모든 카드 disabled |
| 프로필 없음 | `loadProfile()` null → `router.replace('/')` |

### 화면 3. 반복 패턴 4지선다 (`/pattern`)

#### 4-a. ASCII 와이어프레임

```
┌─────────────────────────────────────┐
│ 사주톡                              │  ← h1
├─────────────────────────────────────┤
│                                     │
│ 한 가지만 더 여쭤볼게요.            │  ← text-muted-foreground (small)
│ 일과 관련해서 반복되는 게 있나요?   │  ← 영역별 맞춤 질문 (text-lg)
│                                     │
│ ┌─────────────────────────────────┐ │
│ │ A. 잘 되다가 갑자기 그만두고    │ │  ← 카드
│ │    싶어짐                       │ │
│ └─────────────────────────────────┘ │
│ ┌─────────────────────────────────┐ │
│ │ B. 처음엔 재미있다가 금방 식음  │ │
│ └─────────────────────────────────┘ │
│ ┌─────────────────────────────────┐ │
│ │ C. 남들은 버티는데 나만 못 버팀 │ │
│ └─────────────────────────────────┘ │
│ ┌─────────────────────────────────┐ │
│ │ D. 잘 모르겠다                  │ │
│ └─────────────────────────────────┘ │
│                                     │
│     (선택하면 바로 진행돼요)        │  ← text-xs text-muted-foreground
└─────────────────────────────────────┘
```

**카테고리별 질문·선택지 (코드 기준)**

| 카테고리 | 질문 |
|---|---|
| 이직 | 일과 관련해서 반복되는 게 있나요? |
| 연애 | 연애에서 반복되는 게 있나요? |
| 결혼 | 결혼·파트너십에서 반복되는 게 있나요? |
| 기타 | 삶에서 반복되는 패턴이 있나요? |

#### 4-b. UX 의도

- "한 가지만 더" 문구 — 화면 2까지 거친 사용자 피로 완화. "이게 마지막"임을 암시
- 카드 탭 즉시 전환. 별도 "다음" 버튼 없음 — 탭 수 최소화
- D "잘 모르겠다" 선택지 항상 마지막 — 반복 패턴 스스로 몰라도 이탈 방지
- `active:scale-[0.98]` 눌림 피드백으로 탭 인식 확인

#### 4-c. 인터랙션

- 카드 탭 →
  1. `saveConversation({ ...conv, pattern: option })`
  2. `router.push('/chat')`
- 선택 변경 불가 (탭 즉시 전환)
- 로딩 없음 (localStorage 저장 즉시)

#### 4-d. 상태

| 상태 | 설명 |
|---|---|
| 정상 | 영역에 맞는 4개 카드 표시 |
| 탭 직후 | active:scale-[0.98] 피드백 후 즉시 /chat 이동 |
| 프로필·대화 없음 | null 체크 → `router.replace('/')` |

#### 4-b. UX 의도

- 사주 결과를 먼저 보여줘 "내 사주가 뭔지" 확인 욕구 충족. 해석 전 신뢰 형성
- 해석 스타일 2개 중 선택 — "현실 풀이형"(직장·돈·관계)과 "생활 상담형"(가족·일상·생활). 사용자가 자기 상황에 맞는 톤 선택
- 복사 버튼 — 텍스트 형태의 사주 정보를 클립보드 복사 → 외부 AI 서비스에 붙여넣기 가능. 라우트 이동 없음
- [다시 입력] 버튼 → `/`로 돌아가 재입력. 결과 이상 시 탈출구 제공
- 현재 대운 강조: 대운 테이블에서 isCurrent=true인 항목에 보라색 outline 적용

#### 4-c. 인터랙션

- [다시 입력] 탭 → `router.push('/')`
- [복사] 탭 → `navigator.clipboard.writeText(buildCopyPrompt())` → 버튼 텍스트 "복사됨 ✓" (2초 후 복원)
- [현실 풀이형] 탭 → `saveConversation({ concern: '전반적인 운세', pattern: '일반 상담', tone: 'reality' })` → `router.push('/chat')`
- [생활 상담형] 탭 → `saveConversation({ concern: '전반적인 운세', pattern: '일반 상담', tone: 'daily' })` → `router.push('/chat')`
- 대운·세운·월운 테이블 → 가로 스크롤 가능 (`overflow-x-auto`)

| 상태 | 설명 |

#### 4-b. UX 의도

- **한 채팅창에 모든 대화 누적**. 화면 전환 없이 말풍선이 위로 쌓임. ChatGPT 패턴
- **톤 뱃지**: 헤더에 "현실 풀이형" / "생활 상담형" 소형 뱃지로 사용자가 자기가 선택한 톤 인식 유지
- **B_HOOK → 캘리브레이션 흐름**: 역술가 톤에서만 작동. 짧은 훅(과거 사건 예측)으로 "나를 알고 있구나" 체감 형성 후, 예/아니오/다른형태로 검증. 긍정이면 실제 사건 맥락을 해석에 반영 → 신뢰도 상승
- **상단 카운터 없음**. 내부 로직(`questionCountRemaining`)으로만 관리. 사용자 압박 제거
- **AI 좌측, 사용자 우측 말풍선**. 표준 채팅 UI. rounded-bl-sm / rounded-br-sm으로 방향 표시
- **AI 응답 마크다운 렌더링**(`ReactMarkdown`). 구조화된 해석(섹션 제목, 목록) 표시 가능
- **스트리밍 중 커서**: `animate-pulse` `▋` 로 LLM 생성 중임을 시각 표시
- **사용자가 위로 스크롤 시 자동 스크롤 중단**: 긴 해석 읽는 중 강제 스크롤 방지
- **[이제 됐어요]**: 상태 C·E에서만 노출. 강요 없이 조기 종료 허용
- **상태 E 4지선다**: 카드 탭 전까지 입력창 disabled. 선택 후 활성. "답해야 진행" 구조로 재료 수집 실패 방지
- **화면 5-a 배너**: turnNumber=3(3번 다 씀)인 사용자만 자동 노출. 대화 흐름 속 연속 확장 — 독립 화면 이탈 없음
- **"다음에요"**: 현재 코드에서 `setView('done')` 처리. DB 플래그 저장은 미구현 (§5 항목)

#### 4-c. 인터랙션

**P0-진입 (상태 A)**
- 화면 진입 → 배너 노출 + 1.5초 타이머

**B_HOOK 흐름 (역술가 톤)**
- `START_HOOK` → `/api/hook` 스트리밍 → 훅 말풍선 노출 → `HOOK_DONE` → `C_CALIBRATING`

**P2 루프 — Q&A (상태 C/D/E)**

## 5. [SO 결정 필요] 항목

코드에서 확인은 되나 추가 결정이 필요한 사항.

---

**SO-1. `/result`와 `/concern` 진입 경로 분리**

현재 코드에서 두 경로가 공존한다.

- 경로 A: `/` → `/result` → (해석 스타일 선택) → `/chat`
- 경로 B: `/concern` → `/pattern` → `/chat` (tone 없음)

경로 B로 진입한 `/chat`은 tone=undefined이므로 B_HOOK 없이 바로 B(긴 해석)로 간다.
두 경로가 의도된 것인지, 또는 경로 A를 메인으로 B를 폐기하거나 통합할 계획인지 결정 필요.

현재 상태: `/concern`은 `/result`를 거치지 않고 직접 접근 가능 (URL 직접 입력 가능).

---

**SO-2. "다음에요" 플래그 저장 미구현**

A-1 S13에서 "다음에요 선택 시 플래그 저장 → 3회차 세션 시작 시 1회 재시도"라고 명시됐으나,
현재 코드 `ParentRequestBanner`의 "다음에요" 탭은 `setView('done')`만 실행.
LocalStorage 플래그 저장 없음 → 재시도 로직 미구현.

결정 필요: 이 기능을 빌드할 것인지, MVP에서 생략할 것인지.

---

**SO-3. 부모님 폼에서 실제 입력 데이터 저장 미구현**

`ParentRequestBanner`의 `view='parent'`에서 라디오 선택 후 [저장] 탭은
"두 분 모두" / "두 분 생년월일만" / "한 분만" 선택 시 실제 생년월일시 입력 폼 없이
바로 `setView('done')`만 실행됨.
라디오 선택값(`parentLevel`) 저장도 없음. 데이터 미수집.

결정 필요: 부모님 생년월일시 입력 폼 빌드 여부. 현재 MVP 범위인지.

---

**SO-4. 환경 데이터 저장 미구현**

`view='env'`에서 [저장] 탭도 `setView('done')`만 실행.
`envEconomy`, `envAtmosphere` 상태가 localStorage 또는 API로 저장되지 않음.

결정 필요: SO-3과 동일 — 환경 데이터 수집을 MVP에 포함할 것인지.

---

**SO-5. 2회차 세션 판별 로직 (sessionCount)**

`shouldTriggerInlineChoice`는 `sessionCount >= 2`로 판별.
`sessionCount`는 SUMMARY_DONE 시 +1 저장됨.
초기값 0 → 첫 세션 완료 후 1 → 두 번째 세션부터 2 이상.

그러나 현재 A-2의 경로에서 `/result`를 거쳐 바로 `/chat`으로 진입하는 경우(고민 입력 없음),
concern='전반적인 운세', pattern='일반 상담'으로 저장됨.
이 경로에서 완주 시에도 sessionCount +1이 되는지? → 코드 확인 결과 동일하게 +1됨.
"재방문" 기준이 경로 A(만세력 뷰)와 경로 B(고민 입력 경로)를 동일하게 취급하는지 의도 확인 필요.

---

**SO-6. 상태 E 50% 랜덤 — 디버깅·재현 불가 위험**

A-1에서 이미 "죽일 이유"로 제기됨.
코드 확인: `Math.random() < 0.5` 그대로 구현. 시드 없음.
사용자 재현 불가, A/B 테스트 불가, 버그처럼 보일 위험 동일.

결정 필요: 100% 고정(조건 만족 시 항상 발동) 또는 0% 비활성화 중 선택.

## Claude의 적대적 압박 — 이 화면 설계를 죽일 이유 세 가지

**1. B_HOOK → 캘리브레이션 플로우가 긴 해석 전 진입 장벽**
역술가 톤 선택 사용자는 긴 해석 전에 "훅 스트리밍 읽기 → 예/아니오 탭 → 상세 입력(연도+카테고리) → 확인 → 템플릿 메시지"를 거쳐야 한다. 입력 단계가 이미 많은 상태에서 추가 4~5단계. 사용자가 "이게 뭐야"로 이탈하거나 대충 탭할 위험. 캘리브레이션 품질이 "정확히 기억해서 입력하는 사용자"에 의존한다는 전제도 취약.

**2. 두 진입 경로가 해석 품질을 다르게 만든다**
경로 A(/result → /chat)는 concern='전반적인 운세', pattern='일반 상담'으로 고정. 경로 B(/concern → /pattern → /chat)는 실제 고민과 패턴이 프롬프트에 주입된다. 두 경로의 해석 품질 차이를 사용자가 인식하지 못하면 "어떤 경로로 들어갔냐에 따라 해석이 달라지는" 일관성 문제가 생긴다. `/result`에서 고민 입력 없이 톤만 선택하게 설계한 이유가 A-1에 명시되지 않음.

**3. 상태 14개 중 절반이 역술가 톤 전용 — 코드 복잡도 비대**
B_HOOK, C_CALIBRATING, C_CALIBRATING_DETAIL, C_CALIBRATING_NO, B_ACK — 5개 상태가 tone='reality'|'daily'에서만 진입 가능. 현재 구현된 두 톤(현실 풀이형, 생활 상담형)이 모두 역술가 훅을 사용하므로 사실상 항상 이 경로를 거친다. "역술가 톤 전용"이라는 분기 자체가 미래 톤 확장을 위한 것인지, 또는 현재 설계상 불필요한 복잡도인지 검토 필요.
