### 의도적 보류 (백로그)
- `qna` / `summary` / `hook` 프롬프트 .md 분리 — `interpret`만 1차로 분리 (고빈도 수정 대상). 어드민 인프라는 이미 다수 .md 지원하므로 5분 작업.
- 과거 사건 검증 엔진 — 입력 UI가 없어 보류.
- daily 톤 회귀 테스트 — premium 톤 도입 후 정식 수행 안 함. prompt_checker 도구가 이걸 위해 만들어졌으므로 지인 테스트 중 실시간 가능.

### 알려진 제약
- Vercel Hobby tier 함수 timeout 60초 — 긴 해석 약 12~25초 (안전 마진 충분).
- Supabase Free tier 500MB DB — 10명 × 평균 5KB/세션 = 50KB로 한참 남음.
- Anthropic 비용 — Sonnet 4.6 1세션당 약 $0.05~0.15. 10명 × 평균 3세션 = $4.5 예상.

## 발생한 이슈

### Vercel 배포 시 발생
1. **"No Output Directory named 'public' found"** — Framework Preset이 "Other"로 잡혀서 Next.js 인식 실패. `Next.js`로 수정 → 해결.
2. **`.env.local`에 `/rest/v1` 잘못 포함** — Supabase 새 UI가 일부 화면에서 잘못된 형태 표시. URL을 base만 남기는 형태로 수정 → 해결.
3. **`.md` 파일 lambda 누락 우려** — 선제적으로 `next.config.mjs`에 `outputFileTracingIncludes` 추가 → 배포 후 `/api/interpret` 정상 응답으로 확인.

### 빌드 중 발생
1. **chat 자동 스크롤 UX 충돌** — 사용자가 메시지 작성 시 강제로 하단 끌림. 스마트 스크롤 시도 후 폐기 → 자동 스크롤 완전 제거.
2. **dev 서버 청크 404 (.next 캐시)** — `next build`와 `next dev`의 청크 해시 충돌. `tsc --noEmit`로 타입 검증 + dev 서버 재시작 워크플로 정착.
3. **시스템 프롬프트 핫리로드 안 됨** — 모듈 상수가 dev 서버 시작 때 1회 캐싱 → `getInterpretSystemDaily()` 등 함수형 변환으로 매 호출 재로드.
4. **화면 폭 375px이 데스크톱에서 너무 좁음** — 사용자 피드백 후 640px로 변경 (모바일은 100% 자동).
