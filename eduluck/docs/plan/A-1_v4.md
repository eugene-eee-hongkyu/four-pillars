# eduluck A-1 v4 — 문서를 프로세스로

> 정책 v16 기준. 1차 독자: Eugene (외주 기획자). A-0 v3 확정 후 작성.

---

## 1. A-0 요약 블록

> **핵심 가설:** 학생(초·중·고) 자녀를 둔 30~45세 어머니가, 학년·진로 결정 시점에, 자녀 사주만 입력해 무료 간이 학운 진단을 받은 뒤, 본인 사주를 추가하고 정밀 분석에 결제할 것이다.
>
> **MVP 경계:** 모바일(Expo Router) / **학생(초·중·고) 자녀** 둔 30~45세 어머니 (수도권·광역시) / 무료 간이 → 정밀 진단 첫 결제

---

## 2. Phase 구조 개요 (4 Phase)

```
P0. 진입 & 자녀 사주 수집           (4 Step)
P1. 무료 간이 학운 진단 응답        (3 Step)
P2. 유료 전환 funnel                (4 Step)
    회원가입 + Mock 결제 + 어머니 사주
P3. 정밀 진단 결과 표시             (2 Step)
```

**v1 컷:** P3에서 PDF·대시보드 제거 / P4(매년 갱신) 전체 삭제. → v2 이후 확장.

**왜 컷했나:** 기본 진단 품질이 mom test 통과 못 하면 후행 가치(PDF·대시보드·매년 갱신) 다 무의미. MVP는 **baseline 진단 품질 + 결제 의향**만 검증.

## 3. Phase별 Step 상세 (총 13 Step)

### P0. 진입 & 자녀 사주 수집

**S0.1. 랜딩 진입**
- 사용자: 인스타·맘카페 링크 탭 → 모바일 랜딩
- 시스템: 랜딩 표시(서비스 소개 + "무료 진단" 단일 CTA), 트래픽 소스 트래킹

**S0.2. 무료 진단 시작**
- 사용자: "무료로 시작" CTA 탭
- 시스템: 비회원 세션 시작(UUID 발급, 30일 보존)

**S0.3. 자녀 기본 정보 입력**
- 사용자: 닉네임·성별·**학년 입력 (초1~고3 모두 활성)**
- 시스템: 학년값으로 학년대별 콘텐츠 톤 분기 준비 (초저·초고·중·고 4구간)

**S0.4. 자녀 사주 입력**
- 사용자: 양력/음력 + 생년월일 + 출생시간(모름 옵션) + 출생 지역
- 시스템: 만세력 계산. 시간 모름 시 → 면책 안내 + 이메일 1개 받기(재진입 리마인더 전용)

### P1. 무료 간이 진단 응답

**S1.1. 진단 생성 중**
- 사용자: 로딩 대기 15~25초
- 시스템: AI 호출(자녀 사주만 기반) → 학년대별 콘텐츠 톤(S0.3 분기값) 반영. **약 A4 0.5페이지 (~15~20문장) 분량** 스트리밍

**S1.2. 간이 진단 결과 표시**
- 사용자: 해석 읽으며 스크롤
- 시스템: A4 0.5페이지 본문 + 미니 학운 흐름 차트, 하단 sticky CTA "어머니 사주 추가로 더 자세히"

**S1.3. 결과 후 분기 + 1차 mom test 설문**
- 사용자: sticky CTA 탭 또는 이탈. "이 진단 얼마나 맞다고 느끼시나요? 1~5점" 1문항 설문
- 시스템: 설문 답변 저장(MVP의 핵심 측정 지표), P2 진입 또는 이탈 트래킹

### P2. 유료 전환 funnel

**S2.1. 정밀 진단 가치 안내**
- 사용자: 정밀 vs 간이 비교 페이지 읽음
- 시스템: 정밀 진단 콘텐츠 샘플(텍스트 미리보기) + 가격 표시(단발 3,000원만)

**S2.2. 이메일/비밀번호 회원가입**
- 사용자: 이메일·비밀번호 입력 → OTP 6자리 인증 → 인증 완료
- 시스템: 비회원 세션 데이터를 회원 계정에 연결

**S2.3. Mock 결제**
- 사용자: 결제 카드 정보 입력(real-looking) → "3,000원 결제하기" 탭 → mock 안내 모달 1회 → 확인
- 시스템: 실제 게이트웨이 호출 없음, paid 상태만 갱신

**S2.4. 어머니 사주 입력**
- 사용자: 본인 생년월일시·출생 지역 입력
- 시스템: 만세력 계산 + 자녀-어머니 합충형해·인성 관계 prompt 재료 준비 → P3 정밀 진단 trigger

**P2 흐름 효과:**
- 결제 완료(S2.3) = commitment 확정 → S2.4 정보 입력 sunk cost effect로 완료율 ↑
- funnel 분리 측정: S2.2→S2.3 = 결제 의향 / S2.3→S2.4 = paid 사용자 정보 수집

### P3. 정밀 진단 결과 표시

**S3.1. 정밀 진단 생성 중**
- 사용자: 로딩 대기 45~90초("더 정밀하게 분석 중")
- 시스템: AI 호출(자녀+어머니 사주 종합) → 학년대별 톤 + **A4 1페이지 (~30~40문장) 분량**. 종합 분석 + 학년대별 가이드 + 어머니-자녀 합 시기 분석 + (고등 학년인 경우) 전공·학교 예측 스트리밍

**S3.2. 정밀 결과 표시 + 2차 mom test 설문**
- 사용자: 정밀 해석 읽기 → 종료. "정밀 진단이 결제할 만한 가치였나요? 1~5점" + "실제로 결제했다면 하시겠나요? 1~5점" 2문항 설문
- 시스템: 설문 답변 저장(결제 의향 신호 검증), 세션 종료

## 6. Kill / Go / Hold 판정

**Go** — A-2 진입.

근거 3줄:
1. MVP가 lean. 검증 가설(baseline 진단 품질 + 결제 의향)에 집중, noise 제거됨.
2. P3 PDF·대시보드·P4 매년 갱신 = 후행 가치. baseline 부정확하면 어차피 무가치. 선행 검증이 합리적.
3. 13 Step → A-2에서 화면 9~11개로 매핑 가능. 학년대별 콘텐츠 톤은 한 prompt 분기로 커버.

## Claude의 적대적 압박 — Kill할 이유 세 가지

1. **무료 간이 진단의 baseline mom test가 진짜 통과할지 미검증** — Eugene 본인이 강조한 진짜 검증 가설. 자녀 사주만 + AI 단독으로 산출한 A4 0.5페이지가 "어? 정확하네" 감탄 수준일지 데이터 없음. v1 첫 100명 mom test 평균 3점 미만이면 P2 이하 전체 무의미. **MVP의 진짜 존재 이유가 이 검증** — Kill 이유이자 동시에 Go 이유. S1.3 mom test 설문이 이 측정의 forcing function.

2. **3,000원 mock 결제 시그널의 가격 탄력성 미검증** — 가격 3,000원으로 friction이 거의 없음 → "결제 행위 자체"는 실 결제 의향에 가까운 신호로 검증 가능. 다만 향후 실 가격대(예: 29,900원·79,000원)에서의 의향은 별도 검증 필요. **MVP는 "결제 행위 검증"까지만, 가격 탄력성은 v2 별도 A/B로 분리.** S3.2의 "실제 결제 의향 5점" 설문 결과를 가격대별로 해석하지 말 것.

3. **이메일/비밀번호 회원가입의 conversion 손실로 funnel 지표 오염** — 카카오 한 탭 vs 이메일+비번+인증 = 30~40% conversion 손실 예상. P1→P2 funnel 이탈이 "진단 품질 문제(검증 대상)"인지 "가입 friction(노이즈)"인지 혼동 변수. → v1.5에서 카카오 추가 후 재측정 권장. MVP 자체 funnel 지표는 **보수적 해석** 명문화 필요.

## 후속 메모 (A-2 입력용)

- **v2 이후 확장 로드맵:** P3 PDF + 대시보드 / P4 매년 갱신 / 카카오·네이버 소셜 로그인 / 구독 결제 / 부모 학교·과 옵션 / 아버지 사주 옵션 / 명리 rule-based 엔진 통합 / 자녀(중·고) 직접 사용 화면
- **MVP 핵심 측정 지표 4종:**
  1. P1 mom test 1차 점수 (S1.3) — 진단 품질 baseline
  2. P1→P2 conversion rate — 가치 전환 신호
  3. P3 mom test 2차 점수 (S3.2) — 정밀 진단 가치
  4. S3.2 "실제 결제 의향" 점수 — 결제 funnel 신호
- **mock 결제 정책:** 표시 가격 3,000원. 카드 정보 입력 폼 실제처럼 표시. "결제하기" 탭 시 mock 안내 모달 1회 노출 후 paid 처리. 실 게이트웨이 호출 없음. 가격 탄력성 A/B는 v2 분리.
- **S2.4 paid 후 이탈 처리:** 30일 세션 보존으로 자발 재진입 커버. 자동 리마인더 이메일 발송은 v2 (MVP에선 이탈율만 측정).
- **AI saju 엔진:** AI 단독 (Claude 또는 GPT API). v1 prompt 구성 = 만세력 계산값(천간·지지·십성·신살·12운성·합충형해·대운·세운) + 학년대별 콘텐츠 톤(초저·초고·중·고 4분기) + 성별 contextual layer + 어머니 사주(정밀시) + 자녀-어머니 관계 분석.

### 톤·깊이 참조 (v4 신설) — Eugene 제공 샘플 reading 분석

**분량 기준:**
- 간이 = A4 0.5페이지 ~15~20문장
- 정밀 = A4 1페이지 ~30~40문장 (Eugene 샘플 분량)

**Eugene 샘플 reading 톤 마커 (AI prompt 설계 참조):**
- 친근한 대화체 어미 ("나와요", "보여요", "맞아요")
- 사주 용어 + 즉시 평이한 풀이 (예: "역마살이 드니 인내가 어렵다")
- 사주 분석 → 즉시 실행 가능한 액션 가이드 변환 (영어 이름, 학군지 이동, 학원 선택, 친구 관계, 훈육 방식 등)
- 부모-자녀 합 분석 (예: "아버지 역마살 닮음", "어머니가 잡아주면 이뤄짐")
- 시기별 변화 가이드 (현재 → 학년 진급별 → 입시 전후)
- (고등 학년일 경우) 전공·학교 예측 — "경영·경제 / 중앙대 보임" 같은 구체 결과
